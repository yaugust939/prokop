# Changelog

Все значимые изменения проекта документируются в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
проект следует [семантическому версионированию](https://semver.org/lang/ru/).

## [Unreleased]

### Добавлено
- **Слой политик безопасности** (`security`): правила для команд и путей в
  секции `security` профиля, единая точка решения `allow`/`ask`/`deny` с
  фиксированным приоритетом (жёсткий блок-лист не переопределяется
  настройками), журнал решений в JSONL и подкоманда
  `prokop security show|check|audit`. Диспетчер инструментов переведён на
  политику: запрещающий список берётся из конфигурации, разрешающий снимает
  подтверждение, каждое решение пишется в аудит. Операции со снимками
  проверяют политику путей. Это **слой политик, а не песочница**: изоляции
  процессов и файловой системы нет, и это явно указано в выводе `security show`
  и в документации.
- **Снимки состояния и откат** (`checkpoints`): `prokop checkpoints
  list|create|restore|prune` и инструмент агента `checkpoint` (набор
  `checkpoints`). Снимок сохраняет содержимое файлов и манифест; откат
  безопасен по умолчанию — лишние файлы не удаляются без явного флага, а
  перед восстановлением автоматически создаётся страховочный снимок, поэтому
  откат обратим. Служебные каталоги игнорируются, потолки по размеру файла и
  числу снимков настраиваются секцией `checkpoints` профиля. Реализовано на
  стандартной библиотеке, одинаково на Windows/macOS/Linux.
- **Терминальный интерфейс** (`tui`): `prokop tui` — редактирование ввода,
  история, статусная строка (провайдер, модель, сессия, число ходов),
  потоковый вывод ответа и слэш-команды `/help`, `/status`, `/model`,
  `/provider`, `/new`, `/sessions`, `/clear`, `/quit`. Ход сохраняется в
  хранилище сессий профиля (источник `tui`). Зависимость `prompt_toolkit` —
  опциональная (extra `tui`): без неё команда подсказывает установку и
  предлагает `prokop chat`; без терминала — отказ с кодом `1`. Чистая логика
  (состояние, разбор команд) вынесена в `tui/state.py` и тестируется без TTY.
- **MCP-клиент** (`mcp`): ядро умеет подключать внешние MCP-серверы по stdio
  (JSON-RPC 2.0 на стандартной библиотеке, без MCP SDK) — рукопожатие,
  `tools/list`, `tools/call`, таймауты с завершением процесса. Инструменты
  серверов регистрируются в общем реестре под именами
  `mcp__<сервер>__<инструмент>` и вызываются тем же диспетчером, что и
  встроенные. Серверы описываются секцией `mcp.servers` профиля и по
  умолчанию выключены; недоступный сервер пропускается, не ломая остальные.
  Наблюдение и ручная проверка — подкоманда `prokop mcp list|tools|call`.
- **Командная строка** (`cli`): точка входа `prokop` после установки пакета —
  `turn`, `chat`, `sessions`, `skills`, `providers`, `config`, `doctor`,
  `cron`, `mcp`. Локальные команды работают без ключа модели и без сети; флаг
  `--json` даёт машиночитаемый вывод; коды возврата фиксированы (`0`/`1`/`2`);
  stdio приводится к UTF-8 на всех платформах. Логика не дублируется —
  команды вызывают существующие модули ядра.
- **GUI-автоматизация** (`computer`): инструмент `computer_use` — захват
  экрана/окон (som/vision/ax), клики и ввод по индексам элементов или
  координатам, скролл/драг, клавиши, `set_value`, окна и фокус; набор
  инструментов `gui`; бэкенды cua-driver и локальный Windows (mss +
  pyautogui + pywinauto); мультимодальная доставка скриншотов; скил
  `gui-automation`. Инструмент виден, только когда бэкенд доступен.
- `docs/PLATFORM_NOTES.md` — инварианты и точки, где платформа различается.
- Тесты `tests/test_paths.py` — единый резолвер путей, отсутствие
  платформенных следов и личных абсолютных путей в ядре.
- Тесты `tests/test_cua_backend.py` — покрытие бэкенда `cua-driver`
  (демон-заглушка): захват, действия, ошибки, таймаут, жизненный цикл.

### Исправлено
- **Кодировка вывода команд.** Терминальный бэкенд декодирует stdout/stderr
  дочернего процесса как UTF-8 с заменой (было — в кодировке локали, из-за
  чего на Windows вывод процессов, пишущих UTF-8, приходил искажённым) и
  задаёт ребёнку `PYTHONUTF8=1` / `PYTHONIOENCODING=utf-8`. Явные значения
  из аргумента `env` и снимка сессии сохраняют приоритет. Результат команды
  больше не зависит от локали машины.
- **Универсальность путей.** Два конкурирующих резолвера домашнего каталога
  сведены в один: `prokop.paths` строится на `prokop.home` (`PROKOP_HOME`
  или `~/.prokop/<профиль>`). Убраны ветвление по платформе и старый бренд
  `AgentCore` (`%LOCALAPPDATA%\AgentCore`,
  `~/Library/Application Support/AgentCore`) — раскладка каталогов одинакова
  на Windows, macOS и Linux.
- **Личные пути вычищены.** `orchestrator/reporter.py` больше не хранит
  жёстко прописанный путь к трекеру на машине разработчика: глобальный
  трекер — `HERMES_TRACKER` или `~/.hermes/tasks.md`. MCP-мост не привязан к
  каталогу конкретной машины (ищет пакет через `PROKOP_SRC` / установку /
  относительный путь), берёт домашний каталог из ядра и версию из
  `prokop.__version__`.
- **Кроссплатформенные точки.** `orchestrator/spawn.py`: поиск opencode по
  npm-каталогам текущей ОС, `start_new_session` на POSIX. Завершение дерева
  процессов — `taskkill` на Windows, `killpg` с откатом `SIGKILL → SIGTERM`
  на POSIX (`collect.py`, `backends/local.py`).
- Дублирование логгера устранено: `logging_setup` — реэкспорт `prokop.log`.

### Изменено
- **Дублирование MCP-протокола устранено.** Бэкенд `cua-driver`
  (`computer/cua.py`) переведён на общий MCP-клиент: управление процессом,
  блокировка, построчное чтение, разбор ошибок и таймауты живут в одном месте
  (`prokop/mcp/client.py`). У `CuaBackend` осталась только предметная логика;
  поведение сохранено — рукопожатие не выполняется (демон принимает
  `tools/call` напрямую), добавлен таймаут ожидания ответа (120 с).
- CI гоняет тесты на ubuntu / windows / macos (Python 3.11–3.13) плюс job
  `hygiene` (запрет личных абсолютных путей).
- `Dockerfile` собирается из рабочего дерева (`COPY src`), а не клонирует
  внешний репозиторий.
- Extra `gui` помечен по платформам: `pyautogui`/`pywinauto` — только
  Windows.
- `SOUL.md` платформенно-нейтрален: механика PowerShell вынесена в
  `docs/PLATFORM_NOTES.md`.
- `agent_e2e.py` → `e2e_live.py` (устранён след старого имени `agent_core`).
- README: актуальное число тестов.

## [0.1.0] — 2026-08-25

Первый публичный релиз: ядро универсального агента prokop, реализованное
по поведенческой спецификации.

### Добавлено
- **Цикл агента** (`loop`): пролог → «модель → инструменты → модель» → финализация;
  прерывание / steer / redirect, стриминг, байт-стабильный системный промпт,
  бюджеты итераций и настенных часов, ретраи с классификацией ошибок, аренда сессии.
- **Инструменты** (`tools`): декларативный реестр, наборы с композицией,
  коэрция аргументов по схеме, разрешения и жёсткий блок-лист, прогрессивное раскрытие.
- **Навыки** (`skills`): структура навыка, доступ (список/просмотр/управление),
  создание и патч, куратор жизненного цикла (архив без удаления).
- **Память** (`memory`): контракт провайдеров, менеджер (встроенный первый,
  максимум один внешний), впрыск контекста в пользовательское сообщение.
- **Хранилище сессий** (`store`): SQLite + FTS5 (стандартный и триграммный индексы),
  поиск по сессиям с якорным окном и «букендами», экспорт/импорт.
- **Провайдеры моделей** (`providers`): декларативные профили, реестр с приоритетами,
  провайдер-агностичное переключение модели.
- **Планировщик** (`cron`): разбор расписаний, тикер, исполнение «без агента»,
  доставка, переживание перезапуска.
- **Субагенты** (`subagents`): делегирование, изоляция ребёнка, роли лист/оркестратор,
  бюджеты, асинхронный возврат сводки.
- **Терминальные бэкенды** (`backends`): контракт, снимок окружения, локальный бэкенд,
  обрезка вывода «голова+хвост» со свалкой.
- **Гейтвей** (`gateway`): ключ сессии, нормализованное событие, контракт адаптера,
  авторизация отправителя, защита от параллельных ходов, кэш агентов, подготовка ответа.
- **Интеграция с opencode** через MCP-сервер `prokop`: `prokop_agent_turn`,
  `prokop_agent_schedule_job`, `prokop_agent_list_jobs`, `prokop_agent_run_ticker`,
  `prokop_agent_run_command`; агент `prokop` в переключателе агентов.
- **CI**: прогон тестов на Python 3.11 / 3.12 / 3.13.

### Примечание
- Код реализован по поведенческой спецификации (см. `openspec/`).
- 173 теста на момент релиза.
