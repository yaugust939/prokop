Ядро агента, который делает работу

Большинство «агентов» — обёртка над чатом. prokop — это ядро агента, который работает: вызывает инструменты, помнит контекст между сессиями, планирует отложенные задачи, делегирует подзадачи и исполняет команды. Модель — любая: провайдер меняется настройкой, без правки кода.

Установка 
git clone https://github.com/yaugust939/prokop
cd prokop && pip install -e src

Ядро и обвес, а не конструктор

Модули ядра prokop и их назначение
ЧастьЧто делает
loopЦикл хода: пролог → модель и инструменты → финализация. Стриминг, ретраи, бюджеты, рулевое управление.
toolsДекларативный реестр инструментов, наборы, разрешения, блок-лист, прогрессивное раскрытие.
skillsПроцедурная память: индекс в промпте, жизненный цикл; телеметрия использования — в работе.
memoryПамять между сессиями.
storeХранилище сессий: SQLite и полнотекстовый поиск.
providersСлой модельных провайдеров: смена модели без правки кода.
transportТранспорты, включая адаптеры Telegram и MAX.

Обвес cron (отложенные и периодические задания с доставкой) · subagents (делегирование с изоляцией и бюджетами) · backends (терминальные бэкенды: снимок окружения, обрезка вывода) · gateway.

Каждая часть — отдельный модуль. Ставить целиком не обязательно.

Агент, который ведёт свои навыки сам

skills — это процедурная память. Агент создаёт и правит навыки по итогам работы, ведёт телеметрию использования, журнал изменений с поштучным откатом, и переводит устаревшее в архив вместо удаления. Навыки не свалка: у каждого есть срок жизни и след использования.

Статус: часть в работе

В этой сборке (коммит a21644a) в ядре есть индекс навыков в промпте, прогрессивное раскрытие, жизненный цикл и архив вместо удаления — каталог skills/. Телеметрия использования и журнал изменений с поштучным откатом в сборку не входят: они в работе. Пометка стоит здесь именно поэтому.

Любая модель. Смена — настройкой

  • Провайдер задаётся профилем: режим API, базовый URL, переменные ключа. Код не меняется.
  • Локальный инференс: тот же профиль с другим base_url, включается на площадке заказчика.
  • Российские модели: работа по YandexGPT и GigaChat ведётся. План В этой сборке их нет.

Не привязан к вендору. Не требует внешних API для работы ядра.

Библиотека навыков — отдельно от ядра

Навык в ядре — это каталог с SKILL.md: метаданные, связанные файлы, свой срок жизни. Навыки живут в профиле, ядро остаётся ядром — перечислить их можно командой prokop skills list.

Статус: каталог не опубликован

Публичной библиотеки prokop-skills и индекса хаба в этой сборке нет: обещать каталог, которого нет, нельзя. Команд установки, поиска и аудита навыков в CLI тоже нет — есть prokop skills list.

Три входа

Разработчику агентов

Не пиши цикл, инструменты и память с нуля — собери на готовом ядре. Начни с loop и tools.

Инженеру автоматизации

Планировщик, субагенты, терминальные бэкенды. Агент, который сам планирует и выполняет.

Ценителю открытости

MIT, свой хостинг, любая модель, ноль скрытых ограничений.

Вопросы

Что такое prokop?

Открытое универсальное ядро для построения автономных агентов: цикл исполнения, инструменты, память, планировщик, делегирование и исполнение команд. Поставляется как Python-пакет и Docker-образ.

Чем отличается от других агентных фреймворков?

Даёт ядро и обвес сразу (цикл, инструменты, память, планировщик, субагенты, бэкенды, гейтвей), не привязан к модели (провайдер меняется настройкой), проверен {{TESTS}} тестами и чистой установкой в контейнере, открыт под MIT.

Это бесплатно? Какая лицензия?

Да, открытый код под лицензией MIT — используйте, меняйте, включайте в свои проекты.

Нужен ли API-ключ?

Для живых ходов — да, ключ модельного провайдера (по умолчанию deepseek). Задайте DEEPSEEK_API_KEY. Без ключа работают тесты и сухая установка.

Какие модели поддерживаются?

Любые через слой провайдеров. Встроенные профили: openai-compatible, anthropic-messages, openrouter, deepseek, ollama. Профиль провайдера задаёт режим API, базовый URL и переменные ключа; имя модели задаётся конфигурацией профиля.

Можно ли подключить локальную модель (например, Ollama)?

Архитектура провайдеров это позволяет (встроенный профиль ollama); укажите base_url локального сервера и модель.

Где хранятся данные (сессии, задания)?

В домашнем каталоге профиля — по умолчанию ~/.prokop (переопределяется PROKOP_HOME).

Есть ли защита от опасных команд?

Да: у инструментов есть разрешения и жёсткий блок-лист опасных команд (рекурсивное удаление корня, mkfs, dd на блочные устройства, fork-бомба и т.п.), не выполняемых даже в «свободном» режиме.

Как прогнать тесты? 
cd src && python -m pytest tests -q
