## 1. Аудитория

Из `docs/MARKETING.md` ядра:

1. **Разработчики ИИ-агентов** — нужен каркас, а не писать инфраструктуру.
2. **Инженеры автоматизации** — нужен агент для отложенных и фоновых задач, умеющий исполнять команды.
3. **Пользователи opencode** — нужен готовый агент-помощник и MCP-инструменты.
4. **Те, кто ценит открытость** — MIT, свой хостинг, любая модель.

Главный вход лендинга — первый и второй сегмент. Третий и четвёртый поддержаны в тексте, но не в hero.

## 2. Боль

Собрать агента с нуля дорого и долго: самому писать цикл исполнения, реестр инструментов, память, безопасность вызовов, планировщик, интеграции. Готовые фреймворки при этом привязывают к одному вендору, тащат лишние зависимости и абстракции, не дают памяти, планировщика и делегирования «из коробки», бывают закрыты или обросли лицензионными ограничениями.

Формулировка для страницы: **«Большинство агентов — обёртка над чатом: генерируют текст и на этом заканчивают.»**

## 3. Формула предложения

**Кому:** разработчикам и инженерам автоматизации, которым нужен работающий агент.

**Что:** `prokop` — готовое ядро агента **и обвес** сразу: цикл хода, инструменты, память, хранилище сессий, слой провайдеров, транспорт, плюс планировщик, субагенты, терминальные бэкенды и гейтвей.

**В отличие от:** фреймворков, привязывающих к вендору. Модель меняется настройкой, код не трогается.

**Почему верить:** тесты (число подставляется из сборки), чистая установка в контейнере, лицензия MIT, разворачивается на своём железе.

ЯДРО АГЕНТА · PYTHON · MIT          ← модульная метка (Handjet)

**H1:** Ядро агента, который делает работу

**Лид:** Большинство «агентов» — обёртка над чатом. `prokop` — это ядро агента, который работает: вызывает инструменты, помнит контекст между сессиями, планирует отложенные задачи, делегирует подзадачи и исполняет команды. Модель — любая: провайдер меняется настройкой, без правки кода.

**Блок установки** (моно, с копированием в один клик):

```
git clone https://github.com/yaugust939/prokop
cd prokop && pip install -e src
```

**Три факта:** `{N} тестов` · `MIT` · `Python 3.11+`
где `{N}` — число, посчитанное на сборке, а не вписанное руками.

**Кнопки:** `Открыть на GitHub` · `Что внутри`

### Что внутри

Заголовок: **Ядро и обвес, а не конструктор**

Ядро:

| Часть | Что делает |
|---|---|
| `loop` | Цикл хода: пролог → модель и инструменты → финализация. Стриминг, ретраи, бюджеты, рулевое управление. |
| `tools` | Декларативный реестр инструментов, наборы, разрешения, блок-лист, прогрессивное раскрытие. |
| `skills` | Процедурная память: индекс в промпте, телеметрия использования, жизненный цикл. |
| `memory` | Память между сессиями. |
| `store` | Хранилище сессий: SQLite и полнотекстовый поиск. |
| `providers` | Слой модельных провайдеров: смена модели без правки кода. |
| `transport` | Транспорты, включая адаптеры Telegram и MAX. |

Обвес: `cron` (отложенные и периодические задания с доставкой) · `subagents` (делегирование с изоляцией и бюджетами) · `backends` (терминальные бэкенды: снимок окружения, обрезка вывода) · `gateway`.

Подпись под таблицей: **Каждая часть — отдельный модуль. Ставить целиком не обязательно.**

### Как это выглядит

Заголовок: **Командная строка, а не только чат**

Фрагменты терминала. **Только реальный вывод**, снятый на сборке из клона репозитория. Если команда требует ключа провайдера и не запускается — показывается сама команда и честная пометка, что вывод требует ключа. Придуманный вывод в этот блок не попадает.

### Учится на вашей работе

Заголовок: **Агент, который ведёт свои навыки сам**

Смысл: `skills` — это процедурная память. Агент создаёт и правит навыки по итогам работы, ведёт телеметрию использования, журнал изменений с поштучным откатом, и переводит устаревшее в архив вместо удаления. Навыки не свалка: у каждого есть срок жизни и след использования.

**Статус этого блока подлежит проверке на сборке** — движок навыков в момент подготовки страницы находится в работе, часть модулей может быть ещё не подключена к ядру. Если это так, блок выходит с пометкой статуса, а не как готовая возможность.

### Модели и независимость

Заголовок: **Любая модель. Смена — настройкой**

- Провайдер задаётся профилем: режим API, базовый URL, переменные ключа. Код не меняется.
- Локальный инференс: тот же профиль с другим `base_url`, включается на площадке заказчика.
- Российские модели: работа по YandexGPT и GigaChat ведётся. **На странице указывается текущее состояние, план помечен как план.**

Подпись: **Не привязан к вендору. Не требует внешних API для работы ядра.**

### Сообщество и навыки

Заголовок: **Библиотека навыков — отдельно от ядра**

`prokop-skills` — публичная библиотека личных навыков агента. Ядро остаётся ядром, навыки ставятся и снимаются отдельно. Установка, поиск, инспекция и аудит — командами CLI. Индекс хаба публикуется по `/.well-known/skills/index.json`, поэтому к хабу может подключаться чужой агент, а ваш — к чужим.

**Состояние наполнения библиотеки подлежит проверке на сборке.** Обещать каталог, которого нет, нельзя.

### Кому

Заголовок: **Три входа**

1. **Разработчику агентов.** Не пиши цикл, инструменты и память с нуля — собери на готовом ядре. Начни с `loop` и `tools`.
2. **Инженеру автоматизации.** Планировщик, субагенты, терминальные бэкенды. Агент, который сам планирует и выполняет.
3. **Ценителю открытости.** MIT, свой хостинг, любая модель, ноль скрытых ограничений.

## 5. Чего на странице не будет

- Обещаний MCP-сервера с инструментами, которых нет в репозитории.
- Числа тестов, вписанного руками.
- Придуманного вывода терминала.
- Слов «революционный», «прорывной», «уникальный».
- Церковнославянской лексики в описании продукта. Метафора живёт в форме — знак, палитра, шрифт, — а не в обещаниях.
