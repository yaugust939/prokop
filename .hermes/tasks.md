(`adrian`, `analitik`, `kozma`, `pisar` — образ `artel3/agent-base:3`).

Переключатель: `ARTEL_PROKOP_ROLES=*` (юнит флота + генератор compose).
Отключение — пустое значение.

**Проверено в бою** (задачи через продовую шину, `task.assigned` → SSE-инбокс):

| `prokopiy` | флот | `prokop: ход завершён api_calls=1` → «Ядро prokop на связи.» |
| `marfa` | флот | `api_calls=1` → ответ с характером Марфы |

| `adrian`, `kozma` | контейнер | `prokop: ход завершён api_calls=1` |

Статистика: **7 успешных ходов через ядро, 0 откатов на llm_call, 0 тупиков
инструментов, 0 ошибок Python, 0 перезапусков контейнеров.**

**Защита от зацикливания портирована.** Прежний харнесс останавливал агента,
повторяющего падающий вызов (в артели был случай: 86 вызовов, ни одной записи).
В адаптере: после 3 повторов — указание модели не повторять вызов, после 5 —
прерывание хода через `TurnControl` и честный ответ «данные получить не удалось»
как результат (не `blocked`). Пороги настраиваются
(`ARTEL_PROKOP_FAIL_NOTE`/`ARTEL_PROKOP_FAIL_STOP`).

**Откатобезопасность:** при любой ошибке ядра раннер возвращается к прежнему
`llm_call` — проверено на неверном ключе (prokop вернул None → сработал откат).
Образ `agent-base:2` остаётся на месте для отката контейнеров.

### ⚠️ Найдено при развёртывании

1. **Раннеров три.** Флот импортирует `os3_agent_runner_compat.py`; в контейнерах
   работает свой минимальный `/app/os3-agent-runner.py` (227 строк, без
   инструментов); третий — полный `os3-agent-runner.py` на хосте. Патч только
   одного выглядит успешным, но роль остаётся на прежнем цикле (признак —
   отсутствие строки `prokop:` в логе).
2. **Ключница требует root** (`/root/.config/artel3/master.key`) — диагностика
   адаптера и прогоны задач должны идти под sudo.
3. **`execute()` принимает значение ключа**, а не его имя — ошибка в первом
   тесте дала 401 у обоих путей (и, кстати, подтвердила работу откатa).

### AI Artel: разведка (VM AIRTEL, 192.168.0.60)

- **Стек OS3** — `/docker/artel3`: реестр `config/agents.json` (66 ролей),
  классы `config/agent-classes.json`, секреты `secrets/<role>.env`, vault по роли.
  Роль **`prokopiy` — «Прокопий (Оркестрация)»**; в MAX-боте `id5118006623_bot`.
- **Мозг флота** был — свой раннер на DeepSeek (`llm_call`). **Установленного
  Hermes Agent на сервере нет**: следы — `vault/hermes` (персонаж Марфы),
  `benchmark_hermes`, `.env.bak-prehermes`.
- **`copilot-v2`** — «Копилот Декларанта V.2»; по ADR 0003 ассистент-движком
  должен стать наш prokop через шов `AgentEngine` → `ProkopEngine`. Причина
  отложения — «Windows-специфика и глобальные синглтоны» — **устранена** нашим
  аудитом и подтверждена зелёным прогоном на этой же VM.

### Что дал первый прогон на Linux

537 тестов: локально (Windows) зелёные, на сервере **14 падений**. Причины и
исправления (коммиты `df34be0`, `e163cd8`): тесты запускали литерал `python`
(на Linux только `python3`) → `sys.executable`; в `run_tui` проверка зависимости
шла раньше проверки терминала → порядок исправлен; один тест TUI зависел от
установленного extra. Итог: **537 passed и на Windows, и на Linux**.
