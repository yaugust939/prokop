## ADDED Requirements

### Requirement: Инструмент computer_use с дискриминатором action

Ядро прокопия SHALL предоставлять единый инструмент `computer_use` с параметром `action`-дискриминатором, объединяющим все операции GUI-автоматизации. Схема инструмента MUST следовать формату OpenAI function-calling и включать: `action` (обязательный), режимы захвата, таргетинг по индексу элемента или координатам, параметры ввода (text, keys, value), управление окнами и режим доставки ввода (`background`/`foreground`).

#### Scenario: Схема инструмента в реестре

- **WHEN** инструмент `computer_use` зарегистрирован в реестре инструментов и бэкенд доступен
- **THEN** `openai_schema()` возвращает валидную схему с `action` в `required` и перечислением всех поддерживаемых действий

#### Scenario: Диспетчеризация действия

- **WHEN** инструмент вызван с `action="capture"` и корректными аргументами
- **THEN** выполняется захват и возвращается результат захвата, а не сообщение о неизвестном действии

#### Scenario: Неизвестное действие

- **WHEN** инструмент вызван с `action`, отсутствующим в перечислении
- **THEN** результат содержит явную ошибку с перечнем допустимых действий

### Requirement: Захват экрана и окна (capture)

Инструмент `computer_use` SHALL поддерживать захват экрана/окна в трёх режимах: `som` (скриншот с нумерованными оверлеями на интерактивных элементах + accessibility-дерево), `vision` (чистый скриншот), `ax` (только accessibility-дерево без изображения). Захват MUST уметь таргетиться на конкретное приложение (по имени/pid/window_id) либо на весь экран; MUST ограничивать число элементов AX-дерева параметром `max_elements` (по умолчанию 100, максимум 1000) и сообщать о превышении через `total_elements`/`truncated_elements`.

#### Scenario: Захват в режиме som

- **WHEN** вызван `capture` с `mode="som"`
- **THEN** результат содержит изображение с нумерованными оверлеями и AX-дерево с индексами элементов

#### Scenario: Захват конкретного окна

- **WHEN** вызван `capture` с `app="<имя приложения>"`
- **THEN** захватывается окно указанного приложения, а не активное окно

#### Scenario: Ограничение AX-дерева

- **WHEN** в `capture` указан `max_elements=50` и приложение публикует более 50 элементов
- **THEN** результат содержит не более 50 элементов и поля `total_elements`/`truncated_elements`

### Requirement: Действия указателем

Инструмент `computer_use` SHALL поддерживать действия: `click`, `double_click`, `right_click`, `middle_click`, `drag`, `scroll`. Таргетинг MUST поддерживать индекс элемента из последнего захвата `som` (предпочтительно) и абсолютные координаты `[x, y]`. Действия MUST поддерживать модификаторы (ctrl, shift, alt, win) и параметры `button`, `from_element`/`to_element`, `direction`/`amount`.

#### Scenario: Клик по индексу элемента

- **WHEN** после `capture(mode="som")` вызван `click` с `element=N`
- **THEN** бэкенд выполняет клик по элементу с индексом N

#### Scenario: Клик по координатам

- **WHEN** вызван `click` с `coordinate=[x, y]`
- **THEN** выполняется клик в указанной точке окна

#### Scenario: Скролл

- **WHEN** вызван `scroll` с `direction="down"` и `amount=3`
- **THEN** окно прокручивается на указанное число «кликов» колеса

### Requirement: Ввод текста, клавиш и значений

Инструмент `computer_use` SHALL поддерживать действия ввода: `type` (ввод текста с учётом раскладки), `key` (комбинации клавиш вида `ctrl+s`), `set_value` (прямая установка значения в select/popup/слайдерах без открытия нативного меню), `wait` (пауза до 30 секунд).

#### Scenario: Ввод текста

- **WHEN** вызван `type` с `text="Привет"`
- **THEN** текст вводится в целевое поле

#### Scenario: Комбинация клавиш

- **WHEN** вызван `key` с `keys="ctrl+s"`
- **THEN** бэкенд отправляет комбинацию клавиш

#### Scenario: Установка значения в селекте

- **WHEN** вызван `set_value` с `element=N` и `value="Blue"`
- **THEN** в элементе выбирается значение «Blue» без открытия нативного меню

### Requirement: Управление окнами и приложениями

Инструмент `computer_use` SHALL поддерживать `list_apps` (список запущенных приложений), `list_windows` (список окон), `focus_app` (маршрутизация ввода в приложение без поднятия окна по умолчанию; с `raise_window=true` окно поднимается на передний план). Управление окнами MUST работать с окнами в любом состоянии (видимое, свёрнутое, позади других).

#### Scenario: Список окон

- **WHEN** вызван `list_windows`
- **THEN** возвращается список окон с идентификаторами для последующего таргетинга

#### Scenario: Фокус на приложение без поднятия окна

- **WHEN** вызван `focus_app` с `app="<имя>"` без `raise_window`
- **THEN** ввод маршрутизируется в приложение, окно не поднимается и фокус пользователя не перехватывается

#### Scenario: Фокус с поднятием окна

- **WHEN** вызван `focus_app` с `raise_window=true`
- **THEN** окно приложения поднимается на передний план

### Requirement: Мультимодальная доставка результата

Результаты захвата и действий с `capture_after=true` MUST возвращаться через мультимодальную обёртку `_multimodal`: текстовый блок (сводка + SOM-индексы) и блок изображения `data:image/png;base64`. Текстовые результаты (list_apps, list_windows, ошибки) MUST возвращаться как JSON-строка.

#### Scenario: Захват с изображением

- **WHEN** выполнен `capture` в режиме `som` или `vision`
- **THEN** результат является мультимодальной обёрткой с `content` (text + image_url base64) и текстовой сводкой

#### Scenario: Текстовый результат

- **WHEN** выполнен `list_apps`
- **THEN** результат — валидная JSON-строка со списком приложений

#### Scenario: Проверка после действия

- **WHEN** вызвано действие с `capture_after=true`
- **THEN** результат дополнительно содержит свежий захват после действия

### Requirement: Доступность и конфигурация бэкенда

Инструмент `computer_use` MUST быть доступен только при наличии рабочего бэкенда (локальный Windows-бэкенд или cua-driver через MCP). Доступность MUST определяться через `check_fn` и отсутствовать в схеме, когда бэкенд недоступен. Бэкенд MUST быть подключаемым через абстракцию `ComputerUseBackend`.

#### Scenario: Бэкенд недоступен

- **WHEN** локальный бэкенд не установлен и cua-driver не сконфигурирован
- **THEN** `check_fn` возвращает false и инструмент не появляется в схеме инструментов

#### Scenario: Локальный бэкенд на Windows

- **WHEN** на Windows установлены зависимости локального бэкенда
- **THEN** инструмент доступен и выполняет захват/действия через локальную реализацию

### Requirement: Безопасность и неразрушающий режим работы

Действия, изменяющие состояние (клики, ввод, скролл, фокус), MUST требовать подтверждения при вызове из MCP-контура, если не настроено авто-подтверждение. Захват (`capture`) MUST быть безопасным действием без побочных эффектов. Доставка ввода по умолчанию MUST быть `background` (без перехвата курсора и фокуса пользователя); режим `foreground` MUST быть явным и иметь собственный скоуп подтверждения.

#### Scenario: Захват не требует подтверждения

- **WHEN** вызывается `capture`
- **THEN** действие выполняется без запроса подтверждения

#### Scenario: Действие требует подтверждения

- **WHEN** вызывается `click` в режиме без авто-подтверждения
- **THEN** запрашивается подтверждение перед выполнением

#### Scenario: Фоновая доставка по умолчанию

- **WHEN** действие выполняется без указания `delivery_mode`
- **THEN** ввод доставляется в фоне без перехвата курсора пользователя
