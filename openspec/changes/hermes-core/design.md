## Context

Проект `OBS_Prokopii_1` — оригинальная пересборка универсального агента-диспетчера. Эталон поведения зафиксирован в поведенческой спецификации ядра, эталонный код находится в `reference\` и НЕ доступен команде реализации. Цель этапа — ядро: цикл агента, инструменты, навыки, память, слой моделей. «Обвес» (gateway, мессенджеры, TUI, cron, MCP, бэкенды) — вне рамок этого изменения.

## Goals / Non-Goals

**Goals:**
- Поведенчески воспроизвести пять подсистем ядра по спецификации `specs/`.
- Заложить архитектурные инварианты: байт-стабильный системный промпт, provider-agnostic смена модели, декларативные наборы инструментов, два уровня памяти.
- Обеспечить оригинальность кода (без обращения к `reference\`).

**Non-Goals:**
- Gateway, мессенджеры, TUI/web, cron, MCP-серверы, терминальные бэкенды — следующие фазы.
- Партийное покрытие всех ~40+ инструментов — на этом этапе достаточно ядра и нескольких представительных наборов.
- Миграция/импорт данных из эталона.

## Decisions

1. **Стек: Python 3.11 (asyncio) для ядра, TypeScript/Node для будущего UI/gateway.**
   - *Почему:* совпадает с эталоном (проще сверять поведение), оба рантайма доступны в RU-инфраструктуре; единый asyncio-рантайм для инструментов и памяти.
   - *Альтернативы:* единый TypeScript — отклонён (ядро вокруг SQLite/FTS5 и модель-вызовов удобнее в Python); Rust/Go — отклонён (дороже итерации, не нужно на этапе ядра).

2. **Формат сообщений — OpenAI-совместимый (`role`/`content`/`tool_calls`/`tool_call_id`), рассуждения отдельно.**
   - *Почему:* максимальная совместимость с провайдерами и инвариант «рассуждения не в контенте».

3. **Системный промпт — строится один раз на сессию, кэшируется и персистится; внешняя память впрыскивается в user-сообщение.**
   - *Почему:* сохранение кэша префикса; изоляция «волатильной» хвостовой части от стабильного тела.

4. **Инструменты — декларативный реестр + автообнаружение + наборы с композицией и вычитанием.**
   - *Почему:* единый механизм доступности (`check_fn`), простое включение/отключение по платформе, прогрессивное раскрытие.

5. **Память — SQLite + FTS5 (с триграммами) для сессий; интерфейс подключаемых провайдеров памяти (максимум один внешний).**
   - *Почему:* нулевая внешняя зависимость для хранилища, полнотекстовый поиск любой письменности, расширяемость через контракт провайдера.

6. **Модели — декларативные профили провайдеров + реестр с приоритетом «последний побеждает»; hostname-детекция точным сравнением.**
   - *Почему:* provider-agnostic смена модели без правки кода, безопасное разрешение по URL.

7. **Оригинальность — вся реализация пишется только по `openspec/changes/hermes-core/`; `reference\` запрещён для команды реализации (процедурный барьер).**

## Risks / Trade-offs

- **[Барьер процедурный, не физический]** → контроль диспетчера, запрет `reference\` в промптах реализации.
- **[Большой объём инструментов]** → на этапе ядра реализуем каркас + представительные наборы, остальные — по мере «обвеса».
- **[FTS5 триграммы тяжелы для больших историй]** → фоновый почанковый бэкфил индекса, fail-closed при повреждении.
- **[Совместимость форматов разных провайдеров]** → слой профилей с хуками `prepare_messages`/`build_extra_body`, коэрция аргументов.

## Open Questions

- Порядок выбора первого представительного набора инструментов (ядро: терминал/файлы/поиск/навыки/память) — уточнить на старте реализации.
- Точная схема `config.yaml` (ключи моделей/памяти/наборов) — зафиксировать до реализации, чтобы не переписывать контракты.
