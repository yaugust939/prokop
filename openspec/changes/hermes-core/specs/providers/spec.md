## ADDED Requirements

### Requirement: Профиль провайдера

Система SHALL описывать каждого модельного провайдера декларативным профилем: имя, режим API, псевдонимы, env-переменные ключей, base_url, тип аутентификации и переопределяемые хуки (подготовка сообщений, доп. поля тела запроса, листинг моделей). Профиль MUST быть декларативным и не владеть построением клиента, ротацией ключей или стримингом.

#### Scenario: Провайдер с квирком формата
- **WHEN** провайдер требует особой подготовки сообщений или размещения reasoning-полей
- **THEN** его профиль переопределяет соответствующий хук, а транспорт применяет его без изменения общего кода

### Requirement: Реестр провайдеров с приоритетами

Система SHALL вести реестр провайдеров с ленивым обнаружением (встроенные, пользовательские, pip-плагины) и приоритетом «последний побеждает»: пользовательский плагин того же имени заменяет встроенный, pip-плагины — низший приоритет.

#### Scenario: Пользовательский провайдер заменяет встроенный
- **WHEN** пользовательский плагин регистрирует имя существующего провайдера
- **THEN** пользовательская реализация выигрывает без правки основного кода

#### Scenario: pip-плагин пытается захватить первое имя
- **WHEN** pip-плагин регистрирует имя первопартийного провайдера
- **THEN** встроенная реализация сохраняет приоритет

### Requirement: Провайдер-агностичное переключение модели

Система SHALL позволять переключать модель и провайдера на лету без пересборки кода, при этом системный промпт MUST пересобираться и сохраняться однократно (одноразовая инвалидация кэша префикса).

#### Scenario: Смена модели
- **WHEN** пользователь переключает модель или провайдера
- **THEN** код не изменяется, системный промпт пересобирается и персистится один раз, кэш префикса ломается только в этот момент

### Requirement: Разрешение провайдера по URL

Система SHALL определять провайдера по hostname из base_url при его неуказании, используя точное сравнение хоста (не substring) для защиты от подмены хоста.

#### Scenario: Определение провайдера по URL
- **WHEN** провайдер не задан явно, но задан base_url
- **THEN** провайдер определяется по точному совпадению hostname

### Requirement: Вспомогательные модели

Система SHALL поддерживать отдельную конфигурацию вспомогательных моделей (компрессия, зрение, эмбеддинги, генерация заголовков, поиск по сессиям, переписывание запросов памяти), каждая со своим провайдером, моделью и лимитами.

#### Scenario: Вспомогательная модель компрессии
- **WHEN** выполняется компрессия контекста
- **THEN** используется вспомогательная модель, сконфигурированная для задачи компрессии, независимо от основной модели
