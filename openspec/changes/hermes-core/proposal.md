## Why

Строим оригинальную («чистую», clean room) пересборку универсального агента-диспетчера, совместимую по поведению с эталонным фреймворком, но написанную с нуля по поведенческой спецификации — без копирования исходного кода. Ядро (цикл агента, инструменты, навыки, память, слой моделей) — фундамент, от которого зависит вся последующая «обвеска» (gateway, мессенджеры, TUI, cron, MCP, бэкенды). Специфицируем ядро первым, чтобы зафиксировать контракты и обеспечить оригинальность до написания кода.

## What Changes

- Вводится ядро агента, реализуемое с нуля на Python + TypeScript в `src\`:
  - цикл обработки хода (ввод → планирование → вызов инструментов → результат → память) с прерыванием, перенаправлением и стримингом;
  - декларативная модель инструментов и наборов (toolsets) с диспетчеризацией и механизмом разрешений;
  - система навыков (процедурная память) с созданием, самоулучшением и поиском;
  - состояние сессий и постоянная память с моделью пользователя;
  - провайдер-агностичный слой моделей.
- Спецификация фиксирует поведенческие контракты; детали реализации — в `design.md`.

## Capabilities

### New Capabilities

- `agent-loop`: обработка одного хода пользователя — построение контекста, итеративный цикл «модель → инструменты → модель», прерывание/steer/redirect, стриминг вывода, байт-стабильный системный промпт, обработка ошибок и устойчивость сессии.
- `tools`: реестр инструментов, наборы (toolsets) с композицией, контракт вызова (JSON-схема/JSON-результат), коэрция аргументов, разрешения и блок-листы, прогрессивное раскрытие.
- `skills`: навыки как процедурная память — структура скилла, перечисление/просмотр/управление, создание и самоулучшение, локальное обнаружение и жизненный цикл с куратором.
- `memory`: два уровня памяти — дурабельное хранилище сессий (SQLite + полнотекстовый поиск) и постоянная пользовательская память через подключаемые провайдеры, включая компрессию контекста и модель пользователя.
- `providers`: декларативные профили модельных провайдеров, реестр с приоритетами, провайдер-агностичное переключение модели без изменения кода.

## Impact

- Новая кодовая база `src\` (Python + TypeScript), изолированная от `reference\` барьером clean room.
- Единственный источник истины — `openspec\changes\hermes-core\` (эта спецификация).
- Стек: Python 3.11 (asyncio) для ядра, TypeScript/Node для последующего UI/gateway.
- Без внешних зависимостей от эталона; поведение воспроизводится, код — оригинальный.
