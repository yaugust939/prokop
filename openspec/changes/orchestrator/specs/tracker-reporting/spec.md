## ADDED Requirements

### Requirement: Отчётность в трекер tasks.md с блокировкой

Оркестратор SHALL вести отчётность в трекеры `tasks.md`: глобальные задачи — в `~/.hermes/tasks.md`, проектные — в `<проект>/.hermes/tasks.md`. Запись SHALL выполняться атомарно с файловой блокировкой (паттерн `_FileLock` из `prokop/cron/store.py`: lock-файл рядом с `tasks.md`, чтение → правка → запись). Формат строки: `- [статус] P<0..2> · <исполнитель> · <описание> (#id)`, статусы `[ ]`, `[~]`, `[x]`, `[!]`.

#### Scenario: Одновременные записи не конфликтуют

- **WHEN** две headless-сессии оркестратора завершаются одновременно и обе обновляют один `tasks.md`
- **THEN** обе записи применяются последовательно, файл не повреждается (блокировка сериализует запись)

### Requirement: Задача фиксируется на старте и закрывается по завершении

При старте задачи оркестратор SHALL добавить/обновить строку со статусом `[~]` (для задачи из трекера — обновить найденную по `#id`; для новой — добавить строку с `#id = max+1`). По завершении SHALL обновить строку на `[x]` с кратким резюме результата (1–2 строки) и стоимостью/токенами в скобках; при ошибке/таймауте — на `[!]`.

#### Scenario: Новая задача фиксируется и закрывается

- **WHEN** оркестратор запускает новую задачу
- **THEN** в трекере появляется строка `[~]` с новым `#id`; после успешного завершения строка становится `[x]` с резюме результата

#### Scenario: Существующая задача обновляется по id

- **WHEN** задача пришла из трекера с известным `#id`
- **THEN** оркестратор обновляет найденную строку, а не создаёт новую

#### Scenario: Ошибка фиксируется как заблокированная

- **WHEN** headless-сессия завершилась с ошибкой или по таймауту
- **THEN** строка задачи в трекере обновляется на `[!]` с указанием причины
