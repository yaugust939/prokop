## ADDED Requirements

### Requirement: Создание снимка набора путей

Ядро SHALL создавать снимок указанных путей (файлов и каталогов) в домашнем
каталоге профиля. Снимок MUST сохранять содержимое файлов и MUST описываться
манифестом, перечисляющим путь, вид записи, размер и соответствие блобу.
Снимок MUST иметь идентификатор, метку и время создания. Идентификатор MUST
быть уникальным даже при создании снимков подряд.

#### Scenario: Снимок каталога

- **WHEN** создаётся снимок каталога с файлами
- **THEN** снимок содержит все неигнорируемые файлы каталога и их содержимое

#### Scenario: Снимок отдельного файла

- **WHEN** создаётся снимок одного файла
- **THEN** снимок содержит этот файл, а восстановление возвращает его содержимое

#### Scenario: Кириллица и пробелы в пути

- **WHEN** путь содержит кириллицу и пробелы
- **THEN** снимок создаётся, а восстановление возвращает файл по тому же пути

#### Scenario: Уникальность идентификаторов

- **WHEN** два снимка создаются подряд без задержки
- **THEN** их идентификаторы различаются

#### Scenario: Несуществующий путь

- **WHEN** в наборе указан путь, которого нет
- **THEN** он пропускается, снимок создаётся из остальных путей

### Requirement: Список снимков

Ядро SHALL предоставлять список снимков профиля с идентификатором, меткой,
временем создания, числом файлов и объёмом. Список MUST быть упорядочен от
новых к старым.

#### Scenario: Пустое хранилище

- **WHEN** снимков нет
- **THEN** список пуст и обращение к нему не приводит к ошибке

#### Scenario: Несколько снимков

- **WHEN** создано несколько снимков
- **THEN** список содержит все, самый новый — первым

### Requirement: Восстановление из снимка

Ядро SHALL восстанавливать состояние из снимка: возвращать содержимое
записанных файлов и воссоздавать отсутствующие файлы и каталоги. Восстановление
MUST NOT удалять файлы, которых не было в снимке, если не запрошено удаление
лишних явно. Отчёт о восстановлении MUST перечислять восстановленные пути.

#### Scenario: Возврат изменённого файла

- **WHEN** файл изменён после снимка и выполняется восстановление
- **THEN** содержимое файла совпадает с содержимым на момент снимка

#### Scenario: Воссоздание удалённого файла

- **WHEN** файл удалён после снимка и выполняется восстановление
- **THEN** файл воссоздаётся с содержимым из снимка

#### Scenario: Лишние файлы сохраняются

- **WHEN** после снимка в каталоге появился новый файл и восстановление
  выполнено без явного запроса на удаление лишних
- **THEN** новый файл остаётся на месте

#### Scenario: Удаление лишних файлов по явному запросу

- **WHEN** восстановление выполнено с явным запросом на удаление лишних
- **THEN** файлы, появившиеся после снимка в снятых каталогах, удаляются

#### Scenario: Неизвестный снимок

- **WHEN** запрошено восстановление по идентификатору, которого нет
- **THEN** поднимается понятная ошибка, файлы не изменяются

### Requirement: Страховочный снимок перед восстановлением

Перед восстановлением ядро SHALL создавать снимок текущего состояния
восстанавливаемых путей, чтобы откат был обратим. Отчёт MUST указывать
идентификатор страховочного снимка.

#### Scenario: Откат отката

- **WHEN** выполнено восстановление из снимка
- **THEN** в списке появляется страховочный снимок состояния до восстановления

### Requirement: Пределы хранилища и правила игнорирования

Ядро SHALL пропускать при снятии служебные каталоги и файлы (система контроля
версий, зависимости, кэши, артефакты сборки) и SHALL ограничивать размер
отдельного копируемого файла. Ядро SHALL ограничивать число хранимых снимков,
удаляя самые старые при превышении. Правила игнорирования и потолки MUST
настраиваться в конфигурации профиля.

#### Scenario: Служебный каталог не попадает в снимок

- **WHEN** снимается каталог, содержащий служебный каталог зависимостей
- **THEN** содержимое служебного каталога в снимок не попадает

#### Scenario: Слишком большой файл

- **WHEN** размер файла превышает потолок
- **THEN** файл не копируется, а в отчёте снимка он отмечен пропущенным

#### Scenario: Превышение числа снимков

- **WHEN** число снимков превышает потолок
- **THEN** самые старые снимки удаляются, новые остаются

#### Scenario: Настройка игнорирования

- **WHEN** в конфигурации профиля заданы дополнительные шаблоны игнорирования
- **THEN** соответствующие пути в снимок не попадают

### Requirement: Инструмент агента для снимков

Ядро SHALL предоставлять инструмент, позволяющий агенту создавать снимок,
получать список снимков, восстанавливать из снимка и удалять старые снимки.
Инструмент MUST регистрироваться в наборе `checkpoints` и MUST быть доступен
только при включённом наборе.

#### Scenario: Создание снимка агентом

- **WHEN** агент вызывает инструмент с действием создания снимка
- **THEN** снимок создаётся и в результате возвращается его идентификатор

#### Scenario: Набор выключен

- **WHEN** набор `checkpoints` не включён в конфигурации профиля
- **THEN** инструмент недоступен модели

#### Scenario: Неизвестное действие

- **WHEN** инструмент вызван с неизвестным действием
- **THEN** возвращается ошибка, состояние снимков не меняется

### Requirement: Удаление старых снимков

Ядро SHALL предоставлять удаление старых снимков с сохранением заданного числа
последних. Удаление MUST быть идемпотентным: повторный вызов при отсутствии
лишних снимков MUST NOT приводить к ошибке.

#### Scenario: Удаление лишних

- **WHEN** запрошено удаление с сохранением последних N снимков
- **THEN** остаются N самых новых, остальные удалены вместе с содержимым

#### Scenario: Повторное удаление

- **WHEN** удаление вызвано повторно при отсутствии лишних снимков
- **THEN** ничего не удаляется и ошибка не поднимается
