## Why

У ядра есть контракты памяти и мессенджеров, но **ни одной реализации**:
провайдер памяти объявлен абстракцией, а `memory.provider` из конфигурации
никем не читается (`MemoryManager.set_external` не вызывается ни из одного
места), адаптеры платформ — только ABC. Из-за этого нельзя проверить, что
контракты вообще пригодны к реализации, а паритет с аналогом (у Hermes Agent
реализованы memory-провайдеры и десятки платформ) остаётся декларацией.
См. `docs/PARITY.md`, пункт «реальные адаптеры и memory-провайдеры».

## What Changes

- **Фабрика провайдеров памяти**: `memory.provider` из конфигурации профиля
  наконец подключается — имя разрешается в реализацию, неизвестное имя даёт
  предупреждение и встроенный провайдер, `MemoryManager` собирается одним
  вызовом.
- **Файловый провайдер памяти** (`memory.provider: file`): постоянные факты и
  дайджесты ходов в домашнем каталоге профиля, релевантная подгрузка контекста
  по ключевым словам, инструменты `memory_save` / `memory_search` /
  `memory_forget`, список путей для резервного копирования, ограничение объёма.
- **Адаптер Telegram** (`gateway/telegram.py`): реализация контракта
  `PlatformAdapter` поверх Bot API (HTTP, `httpx`, без новых зависимостей) —
  подключение, отправка с разбиением по лимиту платформы, индикатор набора,
  информация о чате, отправка медиа; нормализация входящих обновлений в
  `InboundEvent`; длинный опрос.
- **CLI**: подкоманда `prokop memory list|search|forget` (локальная, без ключа
  модели) — память видно и можно почистить без кода.
- Конфигурация профиля: `memory.options` для настроек провайдера.

### Modified Capabilities
- `memory`: добавляются требования о разрешении провайдера по конфигурации и о
  файловом провайдере памяти (хранение, релевантная подгрузка, инструменты,
  ограничение объёма, устойчивость к повреждённому хранилищу).
- `messaging`: добавляется требование об адаптере Telegram (операции контракта,
  нормализация входящих событий, отображение ошибок в категории).
- `cli`: добавляется подкоманда `memory`.

## Impact

- Новые файлы: `src/prokop/memory/{file_provider,factory}.py`,
  `src/prokop/gateway/telegram.py`, `src/tests/test_memory_file.py`,
  `src/tests/test_telegram_adapter.py`.
- Изменения: `src/prokop/config.py` (`memory.options`),
  `src/prokop/cli/{main,commands}.py` (подкоманда `memory`).
- Документация: `README.md`, `docs/GUIDE.md`, `docs/PARITY.md`, `CHANGELOG.md`.
- Зависимости не добавляются: память — файлы в профиле, Telegram — HTTP через
  уже используемый `httpx`.
- Риски: сетевые сбои платформы (отображаются в категории ошибки и
  ретраятся по контракту); рост хранилища памяти (ограничение объёма);
  секреты в памяти (хранилище в профиле, а не в проекте; напоминание в
  документации).
