## MODIFIED Requirements

### Requirement: Разрешения и блок-листы

Система SHALL классифицировать опасные команды терминала и запрашивать одобрение, вести жёсткий блок-лист команд, не выполняемых никогда, и применять пользовательский deny-лист по глоб-паттернам. Классификация при вызове инструмента SHALL выполняться политикой безопасности (`prokop.security`): запрещающий список берётся из конфигурации профиля, дополнительно действует разрешающий список, снимающий подтверждение для доверенных команд, а каждое решение SHALL фиксироваться в журнале аудита. Жёсткий блок-лист MUST оставаться непереопределяемым: ни запрещающие, ни разрешающие настройки не могут сделать команду из него выполнимой.

#### Scenario: Опасная команда
- **WHEN** детектор распознаёт опасную команду (например, рекурсивное удаление)
- **THEN** исполнение приостанавливается до одобрения пользователя

#### Scenario: Команда из жёсткого блок-листа
- **WHEN** модель запрашивает выполнение команды из жёсткого блок-листа
- **THEN** команда отклоняется безусловно, независимо от режима разрешений

#### Scenario: Запрет из конфигурации профиля
- **WHEN** команда совпадает с запрещающим шаблоном из секции `security` конфигурации профиля
- **THEN** команда отклоняется без запроса подтверждения

#### Scenario: Разрешённая команда
- **WHEN** команда распознана детектором как опасная, но совпадает с разрешающим шаблоном из конфигурации профиля
- **THEN** подтверждение не запрашивается и команда выполняется

#### Scenario: Решение записано в аудит
- **WHEN** политика приняла решение по команде при вызове инструмента
- **THEN** решение зафиксировано в журнале аудита профиля
