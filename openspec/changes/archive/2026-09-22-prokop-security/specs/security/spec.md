## ADDED Requirements

### Requirement: Политики команд из конфигурации профиля

Ядро SHALL читать правила безопасности из секции `security` конфигурации
профиля: запрещающие и разрешающие шаблоны команд, запрещающие и разрешающие
шаблоны путей, признак ведения журнала. Отсутствие секции MUST означать
отсутствие дополнительных правил и MUST NOT приводить к ошибке.

#### Scenario: Секция отсутствует

- **WHEN** в конфигурации профиля нет секции `security`
- **THEN** действуют только встроенные правила (жёсткий блок-лист и детектор
  опасных команд)

#### Scenario: Пользовательский запрет команды

- **WHEN** команда совпадает с запрещающим шаблоном из конфигурации
- **THEN** решение — запрет, команда не выполняется

#### Scenario: Разрешающий список снимает подтверждение

- **WHEN** команда распознана детектором как опасная, но совпадает с
  разрешающим шаблоном
- **THEN** решение — разрешено, подтверждение не запрашивается

### Requirement: Приоритет правил

Система SHALL применять правила в фиксированном порядке: жёсткий блок-лист
(запрет) → запрещающие шаблоны конфигурации (запрет) → разрешающие шаблоны
(разрешение) → детектор опасных команд (подтверждение) → разрешение. Жёсткий
блок-лист MUST NOT переопределяться настройками.

#### Scenario: Запрет сильнее разрешения

- **WHEN** команда совпадает и с запрещающим, и с разрешающим шаблоном
- **THEN** решение — запрет

#### Scenario: Жёсткий блок-лист непереопределяем

- **WHEN** команда из жёсткого блок-листа совпадает с разрешающим шаблоном
  конфигурации
- **THEN** решение — запрет

#### Scenario: Опасная команда без правил

- **WHEN** команда распознана детектором как опасная и правил для неё нет
- **THEN** решение — требуется подтверждение

### Requirement: Решение по пути

Ядро SHALL принимать решение по пути для операций самого ядра: запрещающие
шаблоны путей дают запрет, разрешающие перекрывают запрет при совпадении,
иначе путь разрешён. Сравнение MUST учитывать и исходную, и приведённую форму
пути, разделители обоих видов и регистр (регистронезависимо на Windows).

#### Scenario: Запрещённый путь

- **WHEN** операция ядра затрагивает путь, совпадающий с запрещающим шаблоном
- **THEN** решение — запрет, операция не выполняется

#### Scenario: Разрешение перекрывает запрет

- **WHEN** путь совпадает и с запрещающим, и с разрешающим шаблоном
- **THEN** решение — разрешено

#### Scenario: Путь без правил

- **WHEN** для пути нет правил
- **THEN** решение — разрешено

#### Scenario: Кириллица и смешанные разделители

- **WHEN** путь содержит кириллицу и разделители обоих видов
- **THEN** решение по нему совпадает с решением по нормализованному пути

### Requirement: Аудит решений

Ядро SHALL фиксировать каждое решение в журнале в каталоге логов профиля.
Запись MUST быть формата JSONL (одно решение — одна строка) и MUST содержать
время, вид (команда или путь), предмет, решение и причину. Сбой записи MUST
NOT прерывать выполнение операции. Журнал MUST читаться по хвосту с
ограничением числа записей.

#### Scenario: Решение зафиксировано

- **WHEN** принято решение по команде или пути
- **THEN** в журнале появляется запись с временем, предметом и решением

#### Scenario: Ошибка записи не ломает операцию

- **WHEN** запись в журнал невозможна
- **THEN** операция продолжается, ошибка фиксируется в логе ядра

#### Scenario: Чтение хвоста

- **WHEN** запрошен хвост журнала с ограничением
- **THEN** возвращаются последние записи в обратном порядке, не более лимита

#### Scenario: Аудит выключен

- **WHEN** ведение журнала отключено в конфигурации профиля
- **THEN** решения не записываются, решения при этом принимаются как обычно

### Requirement: Границы слоя политик

Ядро SHALL явно сообщать, что слой политик управляет решениями ядра и его
инструментов и MUST NOT заявляться как изоляция процессов или файловой
системы. Вывод инспекции политики MUST содержать это указание.

#### Scenario: Инспекция политики

- **WHEN** запрошен показ действующих правил
- **THEN** вывод содержит правила и явное указание, что слой не изолирует
  процессы

#### Scenario: Проверка команды без выполнения

- **WHEN** запрошена проверка команды
- **THEN** выводится решение и причина, команда не выполняется
