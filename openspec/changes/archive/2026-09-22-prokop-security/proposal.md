## Why

У ядра есть классификатор опасных команд (`tools/safety.py`), но он не связан
с конфигурацией: пользовательский deny-лист нигде не читается, разрешающего
списка нет, политики для путей нет, а решения нигде не фиксируются — нельзя
ответить на вопрос «что агент пытался сделать и что ему разрешили». У аналога
(Hermes Agent) есть слой безопасности — это последний гэп P1 в
`docs/PARITY.md`.

Настоящая песочница (изоляция процессов и ФС) платформенно-специфична: Windows
Job Objects, Linux namespaces, macOS sandbox — это вернуло бы ветвление по ОС,
которое мы вычищали. Поэтому делается **кросс-платформенный слой политик**:
явные правила, единая точка решения, аудит. Это не изоляция, и в документации
это сказано прямо.

## What Changes

- Новый пакет `src/prokop/security/`:
  - `policy.py` — единый движок решений: правила для команд (deny/allow),
    правила для путей, итоговое решение `allow` / `ask` / `deny`;
  - `audit.py` — журнал решений в формате JSONL (только добавление, чтение
    хвоста), устойчивый к сбоям записи.
- Конфигурация профиля: секция `security` (deny/allow для команд, deny/allow
  для путей, включённость аудита).
- `tools/dispatcher.py` переводится на политику: deny-лист берётся из
  конфигурации, появляется разрешающий список, каждое решение пишется в аудит.
  Жёсткий блок-лист остаётся непереопределяемым.
- Инструмент `checkpoint` и команда `prokop checkpoints restore` проверяют
  политику путей перед записью.
- CLI: подкоманда `prokop security show|check|audit` (локальная, без ключа
  модели).
- Честная граница возможностей: слой политик управляет решениями ядра и его
  инструментов, но **не** изолирует процессы и не мешает команде, которую
  политика разрешила, сделать что угодно в пределах своих прав ОС.

## Capabilities

### New Capabilities
- `security`: политики команд и путей, единое решение `allow`/`ask`/`deny`,
  приоритет правил, аудит решений, настройка через конфигурацию профиля.

### Modified Capabilities
- `tools`: классификация команд при вызове инструмента выполняется политикой
  безопасности — deny-лист из конфигурации, разрешающий список, аудит решений;
  жёсткий блок-лист остаётся непереопределяемым.
- `cli`: добавляется подкоманда `security`.

## Impact

- Новые файлы: `src/prokop/security/{__init__,policy,audit}.py`,
  `src/tests/test_security.py`.
- Изменения: `src/prokop/config.py` (секция `security`),
  `src/prokop/tools/dispatcher.py` (использование политики),
  `src/prokop/checkpoints/tool.py` и `src/prokop/cli/commands.py` (проверка
  политики путей), `src/prokop/cli/main.py` (подкоманда).
- Документация: `README.md`, `docs/GUIDE.md`, `docs/PARITY.md`, `CHANGELOG.md`.
- Зависимости не добавляются; журнал — файл в каталоге логов профиля.
- Риски: ложное чувство защищённости (снимается явной формулировкой границ в
  документации и в выводе `security show`); рост журнала (чтение по хвосту,
  запись best-effort).
