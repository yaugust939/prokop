## Context

У ядра есть линейный `prokop chat` (`prokop/cli/commands.py`): читает строку,
делает ход, печатает ответ, хранит историю в памяти процесса. Ни
редактирования ввода, ни истории команд, ни статуса, ни сохранения сессии.
У аналога (Hermes Agent) TUI есть — это гэп P1 в `docs/PARITY.md`.

Ограничения:
- **платформенная нейтральность** — инвариант проекта (`docs/PLATFORM_NOTES.md`).
  Полноэкранный интерфейс на stdlib платформенно-нейтрально не сделать:
  `curses` нет в Windows-сборке Python, а `termios`/`msvcrt` вернут ветвление
  по ОС;
- **минимум зависимостей** — базовые зависимости остаются `httpx` + `PyYAML`;
- ядро остаётся ядром: TUI не добавляет новой логики хода, а вызывает
  существующие модули (`AgentTurn`, `SessionStore`, `ProviderRegistry`);
- тесты не должны требовать терминала (в CI его нет);
- ход должен быть виден в хранилище сессий, а не жить только в памяти процесса.

## Goals / Non-Goals

**Goals:**
- Интерактивная сессия с редактированием ввода, историей и статусной строкой.
- Потоковый вывод ответа (дельты по мере генерации).
- Слэш-команды для управления сессией без выхода из интерфейса.
- Ход сохраняется в хранилище сессий профиля (источник `tui`).
- Чистая логика (состояние, разбор команд) вынесена и покрыта тестами без
  терминала.
- Корректная деградация: нет зависимости — понятное сообщение и подсказка
  `prokop chat`; нет терминала — отказ с кодом `1`.

**Non-Goals:**
- Полноэкранные панели, сплиты, вкладки, мышь, скроллбэк.
- Автодополнение путей и упоминаний файлов.
- Собственный рендерер на ANSI-последовательностях (это вернуло бы ветвление
  по ОС — см. «Decisions»).
- Отмена хода по `Esc` (прерывание уже есть в ядре, но подключение клавиши —
  отдельная задача).
- Темы, скины, настраиваемые раскладки клавиш.

## Decisions

### D1: `prompt_toolkit` как опциональная зависимость
Extra `tui` в `pyproject.toml`; импорт ленивый, внутри функции запуска.

- *Рационально*: работает одинаково на Windows/macOS/Linux, даёт
  редактирование, историю, статусную строку и корректную работу с кириллицей
  из коробки; базовая установка ядра не тяжелеет.
- *Альтернатива* (`curses`): отсутствует в Windows-сборке Python — TUI
  работал бы не везде.
- *Альтернатива* (свой рендерер на ANSI + `termios`/`msvcrt`): возвращает
  платформенное ветвление, которое мы только что вычистили.

### D2: Чистая логика отделена от рендеринга
`state.py` не импортирует `prompt_toolkit` и не знает про терминал: состояние
сессии и разбор слэш-команд — обычные функции. `app.py` — тонкий слой,
который читает строку и печатает.

- *Рационально*: в CI нет терминала, но логику можно и нужно тестировать;
  рендеринг не покрывается юнит-тестами осознанно.
- *Альтернатива* (всё в одном модуле): непроверяемо.

### D3: Слэш-команды как единственный способ управления
`/help`, `/status`, `/model`, `/provider`, `/new`, `/sessions`, `/clear`,
`/quit`. Строка, не начинающаяся с `/`, уходит модели.

- *Рационально*: не конфликтует с обычным текстом, привычно, легко
  расширяется; разбор — чистая функция.
- *Альтернатива* (горячие клавиши): сложнее тестировать и документировать.

### D4: Сессия TUI пишется в общее хранилище
При старте создаётся сессия с источником `tui`; каждый ход добавляет
сообщения пользователя и ассистента в `SessionStore`. `/new` создаёт новую
сессию, `/clear` очищает только историю в памяти (не удаляет записи).

- *Рационально*: сессию видно в `prokop sessions list|show`, поведение
  согласовано с остальным ядром; удаление данных из TUI не предусмотрено —
  это необратимая операция, ей не место в интерактивном цикле.
- *Альтернатива* (сессия только в памяти): теряется при выходе.

### D5: Деградация вместо ошибки
Нет `prompt_toolkit` → сообщение с командой установки extra и предложение
`prokop chat` (код `1`). Нет TTY → сообщение и код `1`. Ошибка хода не
завершает интерфейс: печатается и цикл продолжается.

- *Рационально*: TUI — надстройка; его отсутствие не должно выглядеть как
  поломка ядра, а сбой модели не должен выкидывать из сессии.

## Risks / Trade-offs

- [Рендеринг не покрыт тестами] → покрыты разбор команд, состояние,
  деградация, запись в хранилище; рендеринг — тонкий слой поверх
  `prompt_toolkit`.
- [Зависимость не установлена] → D5: понятное сообщение, без падения.
- [Кириллица в терминале] → `prompt_toolkit` работает с юникодом; плюс уже
  есть настройка stdio в CLI.
- [Потоковый вывод конфликтует с отрисовкой промпта] → печать дельт идёт
  между вызовами `prompt()`, когда интерфейс не активен.
- [Разрастание TUI до второго продукта] → Non-Goals и скоуп MVP в tasks;
  расширения — отдельными изменениями.
- [Секреты в истории команд] → история держится в памяти процесса и не
  пишется на диск.

## Migration Plan

1. Добавить пакет `tui` и extra `tui` — базовое поведение не меняется.
2. Добавить подкоманду `prokop tui`.
3. Обновить документацию и `docs/PARITY.md`.
4. Прогнать тесты в матрице ubuntu/windows/macos (TUI-логика тестируется без
   терминала, поэтому матрица проходит).

Откат: удалить пакет `tui` и подкоманду; extra `tui` безвреден.

## Open Questions

- Нужна ли отмена хода по `Esc` внутри TUI? — Пока нет: прерывание есть в
  ядре, подключение клавиши требует управления задачами в цикле.
- Нужен ли экспорт сессии из TUI (`/export`)? — Пока нет: `prokop sessions
  show` уже даёт содержимое.
