## Why

`prokop` умеет быть MCP-**сервером** (мост в opencode), но не умеет быть
MCP-**клиентом**: он не может взять инструменты у внешних MCP-серверов. При
этом частный случай клиента уже есть — `computer/cua.py` руками реализует
JSON-RPC 2.0 к демону `cua-driver` (~60 строк), то есть протокол продублирован
под одну задачу. У аналога (Hermes Agent) MCP-клиент общий — это гэп P1 в
`docs/PARITY.md`. Общий клиент делает ядро расширяемым извне: любая внешняя
возможность (файлы, базы, браузеры, внутренние API) подключается как
MCP-сервер, без правки кода ядра.

## What Changes

- Новый пакет `src/prokop/mcp/`:
  - `client.py` — общий JSON-RPC 2.0 клиент к MCP-серверу через stdio:
    запуск процесса, рукопожатие `initialize` → `notifications/initialized`,
    `tools/list`, `tools/call`, таймауты, корректное завершение;
  - `config.py` — разбор секции `mcp.servers` конфигурации профиля в
    описания серверов (команда, окружение, рабочий каталог, таймаут,
    включённость);
  - `runtime.py` — владение живыми клиентами и мост инструментов в
    `ToolRegistry` (пространство имён `mcp__<сервер>__<инструмент>`).
- Конфигурация профиля: новая секция `mcp.servers` (аддитивно, без ломки
  существующих ключей).
- Набор инструментов `mcp` в `tools/toolsets.py`.
- CLI: подкоманда `prokop mcp list|tools|call` (локальная, без ключа модели).
- Реализация клиента не тянет MCP SDK: только стандартная библиотека
  (`asyncio`, `subprocess`, `json`) — как в `computer/cua.py`.

## Capabilities

### New Capabilities
- `mcp-client`: общий клиент MCP-серверов — конфигурация серверов, запуск и
  рукопожатие, перечисление инструментов, вызов инструмента, мост в реестр
  инструментов с пространством имён, таймауты и корректное завершение.

### Modified Capabilities
- `cli`: добавляется подкоманда `mcp` (перечисление серверов, список
  инструментов сервера, вызов инструмента) — локальная, без ключа модели.

## Impact

- Новые файлы: `src/prokop/mcp/{__init__,client,config,runtime}.py`,
  `src/tests/test_mcp_client.py`.
- Изменения: `src/prokop/config.py` (поле `mcp`), `src/prokop/tools/toolsets.py`
  (набор `mcp`), `src/prokop/cli/{main,commands}.py` (подкоманда `mcp`).
- Документация: `README.md`, `docs/GUIDE.md`, `docs/PARITY.md`, `CHANGELOG.md`.
- Зависимости не добавляются.
- Дублирование протокола в `computer/cua.py` остаётся; перевод cua-driver на
  общий клиент — отдельная задача (вне этого изменения), чтобы не
  дестабилизировать GUI-автоматизацию.
- Риски: произвольные имена MCP-инструментов недопустимы как имена функций
  модели (санитайзинг + карта соответствия); внешний процесс может не
  ответить (таймаут с завершением процесса); инструменты внешнего сервера
  расширяют поверхность доступа (по умолчанию серверы выключены, включаются
  явно в конфигурации профиля).
