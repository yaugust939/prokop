## Context

`LocalBackend` (`src/prokop/backends/local.py`) исполняет команды через
`subprocess.Popen(..., text=True)`. При `text=True` Python декодирует вывод
в кодировке локали (`locale.getpreferredencoding(False)`). На Windows это
OEM-кодировка консоли, поэтому дочерний процесс, пишущий UTF-8 (типичный
случай — `python`-скрипты, CLI-инструменты, современные утилиты), даёт
искажённый текст.

Наблюдение: с `PYTHONIOENCODING=utf-8` в окружении тест
`test_export_var_survives_spawns` получает `РїСЂРµРѕРґРѕР»РµРЅРѕ` вместо
`преодолено`. То есть результат бэкенда зависит от переменных окружения
машины, а не от контракта.

Соседний модуль `orchestrator/spawn.py` уже решает эту задачу иначе и
правильно: `encoding="utf-8", errors="replace"`. Терминальный бэкенд
отстаёт от него.

Ограничения:
- нельзя ломать существующие требования бэкендов (снимок окружения,
  детекция `cd`, обрезка вывода, отделение инфраструктурного сбоя);
- нельзя добавлять зависимости;
- поведение должно быть одинаковым на Windows, macOS и Linux;
- конфигурация бэкенда (`backends/config.py`) может задавать окружение —
  приоритет пользовательских значений должен сохраниться.

## Goals / Non-Goals

**Goals:**
- Кодировка вывода команд детерминирована и не зависит от локали машины.
- Дочерний процесс получает UTF-8-режим вывода, чтобы обе стороны говорили
  на одной кодировке.
- Существующее поведение бэкенда (включая снимок окружения) не меняется.

**Non-Goals:**
- Транскодирование OEM-вывода нативных утилит Windows (реверс cp866 → UTF-8):
  неоднозначно и вне контракта.
- Изменение формата `CommandResult` или окна обрезки вывода.
- Поддержка произвольных кодировок по флагу.

## Decisions

### D1: Фиксированная UTF-8-декодировка вместо кодировки локали
`Popen(..., text=True, encoding="utf-8", errors="replace")`.

- *Рационально*: совпадает с `orchestrator/spawn.py`, убирает зависимость от
  локали, не падает на нераскодируемых байтах.
- *Альтернатива* (кодировка локали + `errors="replace"`): оставляет
  моджибейк для UTF-8-вывода — исходный дефект.

### D2: UTF-8-режим задаётся дочернему процессу
В окружение команды добавляются `PYTHONUTF8=1` и `PYTHONIOENCODING=utf-8`,
если эти переменные ещё не заданы вызывающим кодом.

- *Рационально*: Python-дочерние процессы (основной сценарий бэкенда) пишут
  ровно ту кодировку, которую декодирует родитель.
- *Альтернатива* (только декодировать): для Python-детей работает, но
  оставляет расхождение, если ребёнок сам выберет кодировку по локали.

### D3: Приоритет слоёв окружения
Порядок сборки: окружение процесса → UTF-8-режим (перекрывает окружение
процесса) → явные слои вызывающего кода (аргумент `env`, затем переменные
снимка сессии).

- *Рационально*: переменные машины (локаль, `PYTHONIOENCODING` из шелла или
  CI) не влияют на результат — это и есть суть исправления; при этом явное
  переопределение из кода или снимка сессии сохраняется.
- *Альтернатива* (добавлять UTF-8 только при отсутствии ключа): оставляет
  зависимость от окружения машины — исходный дефект.

### D4: Дефект фиксируется тестом, устойчивым к внешней среде
Тест запускает дочерний процесс, печатающий кириллицу, и проверяет точное
совпадение — при любой `PYTHONIOENCODING` в окружении.

- *Рационально*: регресс ловится независимо от того, как запущена сессия
  тестов.

## Risks / Trade-offs

- [Нативные утилиты Windows печатают в OEM-кодировке (`dir`, `chcp`)] →
  вывод таких команд даст символы замены вместо моджибейка. Осознанный
  компромисс в пользу детерминизма; фиксируется в `docs/PLATFORM_NOTES.md`.
- [Скрипты, зависящие от точной кодировки локали] → переменные UTF-8 можно
  переопределить через аргумент `env` или снимок сессии (D3).
- [Расхождение с `CommandResult.stderr`] → декодируется тем же правилом, что
  и stdout, дополнительных изменений не требуется.

## Migration Plan

1. Изменить параметры `Popen` и сборку окружения в `LocalBackend.run`.
2. Добавить тест на кириллицу, устойчивый к внешней `PYTHONIOENCODING`.
3. Прогнать набор тестов в матрице ubuntu/windows/macos.

Откат: вернуть `text=True` без явной кодировки — контракт `CommandResult`
не меняется, откат безопасен.
