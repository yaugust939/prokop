## Context

Прокопий — headless-ядро агента (Python 3.11+, asyncio): цикл хода `loop/`, реестр инструментов `tools/` (контракт JSON-схема → JSON-результат, мультимодальная обёртка `_multimodal`), наборы `tools/toolsets.py`, система навыков `skills/`, терминальные бэкенды `backends/`. В opencode прокопий подключается MCP-сервером `~/.config/opencode/mcp-servers/prokop_mcp.py` (5 инструментов: turn/schedule_job/list_jobs/run_ticker/run_command).

GUI-автоматизации в ядре нет. В эталоне `reference/tools/computer_use/` (hermes-agent) реализован проверенный паттерн: один инструмент `computer_use` с action-дискриминатором, захват в режимах `som`/`vision`/`ax`, таргетинг по индексам элементов, фоновый ввод без кражи курсора, бэкенды через cua-driver (MCP over stdio) и локальную реализацию. Прокопий строился по поведенческой спецификации этого эталона — переносим возможность в ядро оригинальной реализацией.

## Goals / Non-Goals

**Goals:**
- Инструмент `computer_use` в ядре прокопия: захват (som/vision/ax), клики, ввод, скролл/драг, клавиши, окна/фокус, `set_value`, `wait`.
- Мультимодальная доставка скриншотов через существующий контракт `_multimodal`.
- Подключаемые бэкенды: абстракция `ComputerUseBackend` + локальный Windows-бэкенд + cua-driver через MCP.
- Новый набор инструментов `gui`; инструмент доступен только при рабочем бэкенде (`check_fn`).
- Проброс `computer_use` через MCP-обёртку и скил `gui-automation`.

**Non-Goals:**
- Браузерная автоматизация (в opencode уже есть playwright MCP с vision).
- Запись/воспроизведение макросов, скриптовый язык автоматизации.
- Облачные/удалённые десктоп-бэкенды (только локальный хост).
- Собственный UI-дашборд прокопия.

## Decisions

### D1: Один инструмент `computer_use` с action-дискриминатором

Вместо десятка мелких инструментов (`screenshot`, `click`, `type`, ...) — единая схема с `action` (как в эталоне). **Почему:** компактная схема = меньше токенов на каждый вызов модели; дискриминатор упрощает диспетчеризацию и разрешения (один инструмент → одно правило allow/ask). **Альтернативы:** отдельные инструменты — отклонено (раздувание схемы, MCP-список).

### D2: Абстракция бэкенда и две реализации

`ComputerUseBackend` (ABC): `capture(...)`, `click(...)`, `type(...)`, `key(...)`, `list_windows(...)`, `focus_app(...)` и т.д. Реализации:
1. **Локальный Windows-бэкенд** (`windows.py`): `mss` (скриншоты), `pyautogui` (ввод), `pywinauto` UIA (дерево элементов + SOM-разметка). Включён по умолчанию при наличии зависимостей.
2. **cua-driver бэкенд** (`cua.py`): MCP-клиент over stdio к `cua-driver` (macOS/Windows/Linux), как в эталоне — фоновый ввод без кражи курсора.

**Почему:** локальный бэкенд даёт работу «из коробки» на Windows (главный хост пользователя); cua-driver — кроссплатформенность и безопасный фоновый режим. **Альтернатива:** только cua-driver — отклонено (лишняя установка для базового сценария).

### D3: SOM-оверлеи для локального бэкенда

`capture(mode="som")` на Windows: снимок окна (mss) + UIA-дерево (pywinauto) → рисование нумерованных рамок на изображении (PIL) → AX-дерево с индексами. **Почему:** повторяет контракт эталона (клик по `element=N`). Для cua-driver SOM берётся готовым от драйвера. **Риск:** UIA не покрывает все элементы (графика) — тогда режим `ax`/`vision` + координаты.

### D4: Мультимодальный контракт без новых механизмов

Результаты захвата — обёртка `{"_multimodal": true, "content": [text, image_url(base64)], "text_summary": ...}`, уже поддержанная `validate_result()` в `tools/registry.py`. **Почему:** ноль изменений контракта ядра; vision-провайдеры получают изображение, текстовые — сводку.

### D5: Доставка через toolsets + MCP-проброс

Инструмент регистрируется в наборе `gui` (не в `core`/`coding`) — принцип узкого ядра из руководства эталона. В MCP-обёртке `computer_use` добавляется отдельным инструментом; разрешения (ask/allow) настраиваются в opencode.json. **Почему:** каждый инструмент в `core` платится на каждом вызове модели; GUI — опциональная возможность.

### D6: Безопасность по умолчанию

`capture` — без побочных эффектов (без подтверждения). Действия (click/type/key/scroll/focus/...): запрос подтверждения из MCP-контура, если нет авто-allow; `delivery_mode="background"` по умолчанию (без кражи курсора); `foreground` — явный, отдельный скоуп подтверждения.

## Risks / Trade-offs

- [UIA не покрывает приложение (canvas, игры, некоторые веб-обёртки)] → Режимы `vision`/`ax` + таргетинг по координатам; документация ограничений.
- [Скриншоты крупные → расход контекста модели] → Сжатие/масштабирование PNG, `max_elements` для AX, лимит размера результата инструмента (`result_limit`).
- [Зависимости локального бэкенда тяжеловесны (pyautogui, pywinauto)] → Опциональные (`check_fn`); при их отсутствии инструмент скрыт или работает через cua-driver.
- [Фоновый ввод на Windows не гарантирован для всех приложений] → `focus_app`/`foreground` как явный путь; честные ошибки бэкенда.
- [Совместимость с `reference` падает после публикации прокопия] → Поведение фиксируется спеками (`specs/computer-use`), реализация оригинальная.

## Migration Plan

1. Пакет `src/prokop/computer/` (schema, backend ABC, windows, cua, capture, tool).
2. Регистрация инструмента + набор `gui` в `tools/toolsets.py` + тесты.
3. Обновление MCP-обёртки `prokop_mcp.py` (вне репо) — инструмент `computer_use`.
4. Скил `gui-automation` в каталоге скилов прокопия + сценарии.
5. Документация: `docs/GUIDE.md`, `docs/PRODUCT_SPEC.md`, `CHANGELOG.md`.
6. Откат: снятие инструмента из MCP-обёртки и набора `gui`; ядро остаётся совместимым.
