## ADDED Requirements

### Requirement: Хранилище сессий

Система SHALL хранить состояние сессий в локальной SQLite-базе с таблицами для сессий, сообщений, снапшотов системных промптов и учёта использования модели. Все пути MUST резолвиться через единый резолвер домашнего каталога профиля, а не жёстко.

#### Scenario: Запись транскрипта
- **WHEN** ход завершается
- **THEN** сообщения хода сохраняются в хранилище сессий с учётом токенов по модели/задаче

#### Scenario: Несколько профилей
- **WHEN** создаётся изолированный профиль
- **THEN** его состояние пишется в собственный домашний каталог, резолвимый единой функцией

### Requirement: Полнотекстовый поиск сообщений

Система SHALL предоставлять полнотекстовый поиск по сообщениям сессий (FTS5), включая триграммный индекс для подстрочного поиска по любым письменностям. Запросы MUST санитизироваться от спецсимволов FTS5.

#### Scenario: Поиск по тексту сообщения
- **WHEN** агент ищет прошлые сообщения по фразе
- **THEN** возвращаются релевантные сниппеты с учётом подстрочного совпадения

### Requirement: Поиск по сессиям с якорным окном

Система SHALL при поиске по сессиям возвращать не только сниппеты, но и якорное окно вокруг найденного сообщения с «букендами» (первые/последние сообщения разговора), чтобы одним вызовом получить и цель, и развязку разговора.

#### Scenario: Поиск длинного разговора
- **WHEN** агент ищет сообщение в длинной сессии
- **THEN** возвращается найденный сниппет плюс первое и последнее сообщения разговора

### Requirement: Компрессия контекста

Система SHALL сжимать средние ходы в сводку при приближении к порогу токенов, защищая «голову» и «хвост» истории, не разрывая пары «вызов инструмента → результат», и маркируя сводку детерминированным префиксом. Сводка MUST генерироваться вспомогательной моделью с фолбэком на статический шаблон.

#### Scenario: Приближение к порогу токенов
- **WHEN** размер контекста подходит к порогу
- **THEN** средние ходы сжимаются в маркированную сводку, голова и хвост сохраняются, пары вызов/результат не разрезаются

### Requirement: Провайдеры памяти

Система SHALL поддерживать подключаемые внешние провайдеры памяти, активируемые именем через конфиг, с контрактом инициализации, prefetch/sync, инструментами и хуками. Встроенный провайдер MUST быть первым, и одновременно MUST быть активен максимум один внешний провайдер.

#### Scenario: Активация внешнего провайдера
- **WHEN** в конфиге задан `memory.provider`
- **THEN** указанный внешний провайдер инициализируется, а встроенный остаётся первым

#### Scenario: Сбой одного провайдера
- **WHEN** один из провайдеров памяти падает
- **THEN** сбой не блокирует остальных провайдеров

### Requirement: Впрыск контекста памяти

Система SHALL впрыскивать префетч-контекст памяти в пользовательское сообщение (не в системный промпт), оборачивая его в маркированный блок, который вычищается из стрима и повторного ввода.

#### Scenario: Впрыск контекста памяти
- **WHEN** перед ходом предзагружается контекст памяти
- **THEN** он добавляется в пользовательское сообщение в маркированном блоке, не изменяя системный промпт

### Requirement: Портабельность состояния

Система SHALL поддерживать экспорт (одной сессии/всех сессий в JSONL) и импорт с валидацией и лимитами, пропуском существующих id и отсоединением дочерних сессий без родителей.

#### Scenario: Импорт дампа сессий
- **WHEN** импортируется набор сессий
- **THEN** существующие id пропускаются, дочерние сессии без родителей отсоединяются, live-состояние сбрасывается
