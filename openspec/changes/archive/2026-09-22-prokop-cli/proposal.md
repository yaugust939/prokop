## Why

Сейчас ядро `prokop` нельзя запустить как самостоятельную программу: у пакета
нет точки входа, и единственный способ им воспользоваться — писать Python-код
или подключать его как MCP-сервер к opencode. У зрелого аналога (Hermes Agent)
есть CLI и TUI, поэтому по этому пункту `prokop` заведомо «хуже» — см.
`docs/PARITY.md`, гэп P1. Нужна точка входа, которая делает ядро
самодостаточным: запуск хода, работа с сессиями, планировщиком, навыками и
провайдерами из терминала, одинаково на Windows, macOS и Linux.

## What Changes

- Новый пакет `src/prokop/cli/` — разбор аргументов и диспетчеризация команд
  поверх существующих модулей ядра (без дублирования логики).
- Точка входа в `pyproject.toml`: `[project.scripts] prokop = "prokop.cli:main"`,
  то есть команда `prokop` после установки пакета.
- Команды MVP:
  - `prokop --version` / `prokop --help`;
  - `prokop turn "<запрос>"` — один ход агента через модель из конфигурации;
  - `prokop chat` — построчный REPL-цикл ходов в рамках сессии;
  - `prokop sessions list|show|search` — чтение хранилища сессий;
  - `prokop cron list|add|tick` — планировщик;
  - `prokop skills list` — навыки профиля;
  - `prokop providers list` — реестр провайдеров;
  - `prokop config show` — действующая конфигурация профиля;
  - `prokop doctor` — проверка окружения (каталог профиля, конфигурация,
    ключ модели, доступность бинарей);
- Кроссплатформенный stdio: UTF-8 на входе/выходе, корректная работа с
  кириллицей и пробелами в путях; никаких личных абсолютных путей.
- Коды возврата пригодны для скриптов: `0` — успех, `1` — ошибка
  пользователя/конфигурации, `2` — ошибка исполнения.
- Команды, требующие сети (модель), отделены от локальных: локальные
  (`sessions`, `skills`, `providers`, `config`, `doctor`, `cron`) работают без
  ключа модели.

## Capabilities

### New Capabilities
- `cli`: точка входа `prokop` — разбор команд, диспетчеризация, форматы вывода
  (`text`/`json`), коды возврата, кроссплатформенный stdio, справка.

## Impact

- Новые файлы: `src/prokop/cli/__init__.py`, `src/prokop/cli/main.py`,
  `src/prokop/cli/commands.py`, `src/prokop/cli/stdio.py`,
  `src/tests/test_cli.py`.
- `src/pyproject.toml` — секция `[project.scripts]`.
- Зависимости не добавляются: только стандартная библиотека (`argparse`) и
  существующие модули ядра.
- Документация: `README.md` (быстрый старт), `docs/GUIDE.md` (раздел CLI),
  `docs/PARITY.md` (закрытие гэпа P1).
- CI: тесты CLI гоняются в существующей матрице ubuntu/windows/macos.
- Риски: расхождение вывода CLI и поведения ядра (снимается тем, что команды
  вызывают те же модули); кодировка консоли на Windows (снимается настройкой
  stdio).
