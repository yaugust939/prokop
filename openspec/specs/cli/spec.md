# Cli Specification

## Purpose

Точка входа `prokop`: разбор команд, диспетчеризация, форматы вывода, коды возврата, кроссплатформенный stdio.

## Requirements

### Requirement: Точка входа `prokop`

Пакет SHALL предоставлять исполняемую команду `prokop`, доступную после
установки пакета, без дополнительной настройки. Команда MUST выводить версию
по `--version` и справку по `--help` / без аргументов. Справка MUST перечислять
доступные подкоманды и MUST быть доступна на каждой подкоманде.

#### Scenario: Версия
- **WHEN** выполняется `prokop --version`
- **THEN** выводится версия пакета `prokop` и код возврата равен `0`

#### Scenario: Справка без аргументов
- **WHEN** команда `prokop` запущена без аргументов
- **THEN** выводится справка со списком подкоманд и код возврата равен `0`

#### Scenario: Неизвестная команда
- **WHEN** указана несуществующая подкоманда
- **THEN** выводится сообщение об ошибке и код возврата равен `1`

### Requirement: Коды возврата пригодны для скриптов

CLI SHALL возвращать `0` при успехе, `1` при ошибке пользователя или
конфигурации и `2` при ошибке исполнения. Ошибки разбора аргументов MUST
возвращать `1`, а не стандартный для парсера аргументов `2`.

#### Scenario: Успешная команда
- **WHEN** команда выполнена без ошибок
- **THEN** код возврата равен `0`

#### Scenario: Ошибка конфигурации
- **WHEN** для сетевой команды отсутствует ключ модели
- **THEN** выводится понятное сообщение и код возврата равен `1`

#### Scenario: Ошибка исполнения
- **WHEN** вызов модели завершается инфраструктурной ошибкой
- **THEN** код возврата равен `2`

#### Scenario: Неверные аргументы
- **WHEN** команде передан недопустимый аргумент
- **THEN** код возврата равен `1`, а не `2`

### Requirement: Форматы вывода

CLI SHALL по умолчанию выводить человекочитаемый краткий текст и SHALL
поддерживать флаг `--json`, переключающий вывод в машиночитаемый формат.
JSON-вывод MUST быть валидным, в UTF-8 и MUST сохранять не-ASCII символы
как есть (без экранирования).

#### Scenario: Текстовый режим по умолчанию
- **WHEN** команда выполнена без флага `--json`
- **THEN** вывод ориентирован на человека и не обязан быть валидным JSON

#### Scenario: Машинный режим
- **WHEN** команда выполнена с `--json`
- **THEN** вывод является валидным JSON и разбирается парсером без ошибок

#### Scenario: Кириллица в JSON
- **WHEN** результат содержит кириллицу и запрошен `--json`
- **THEN** символы выводятся как есть, без `\uXXXX`-экранирования

### Requirement: Кроссплатформенный ввод-вывод

CLI SHALL работать одинаково на Windows, macOS и Linux. Потоки ввода-вывода
MUST приводиться к UTF-8 там, где это поддерживается платформой, иначе
настройка MUST быть безоперационной (no-op) и MUST NOT приводить к падению.
Кириллица и пробелы в путях MUST NOT искажаться.

#### Scenario: Кириллица в выводе
- **WHEN** команда выводит текст с кириллицей
- **THEN** текст выводится без ошибок кодировки и без замены символов

#### Scenario: Платформа без поддержки перенастройки потока
- **WHEN** поток не поддерживает смену кодировки
- **THEN** настройка не выполняется, команда продолжает работу

### Requirement: Состояние резолвится только через ядро

CLI MUST определять расположение состояния (профиль, конфигурация, сессии,
логи, задания) исключительно через модули ядра `prokop.home` и `prokop.paths`.
CLI MUST NOT содержать личных абсолютных путей и MUST NOT ветвиться по
платформе ради путей. Переменная `PROKOP_HOME` MUST переопределять базу
каталогов.

#### Scenario: Переопределение базы
- **WHEN** задана переменная `PROKOP_HOME`
- **THEN** все команды читают и пишут состояние внутри этого каталога

#### Scenario: Отсутствие личных путей
- **WHEN** исходники CLI проверяются на личные абсолютные пути
- **THEN** совпадений не найдено

### Requirement: Локальные команды автономны

Команды инспекции и диагностики SHALL работать без ключа модели и без
доступа к сети: `sessions`, `skills`, `providers`, `config`, `doctor`, `cron`.
Обращение к сети MUST происходить только в командах хода агента.

#### Scenario: Инспекция без ключа
- **WHEN** ключ модели не задан и выполняется локальная команда
- **THEN** команда завершается успешно с кодом `0`

#### Scenario: Диагностика окружения
- **WHEN** выполняется `prokop doctor`
- **THEN** выводится состояние каталога профиля, конфигурации, ключа модели и
  внешних бинарей, при этом команда не обращается к модели

### Requirement: Ход агента

Команда `turn` SHALL выполнять один ход агента через модель, выбранную в
конфигурации профиля, и выводить итоговый ответ. При отсутствии ключа модели
команда MUST завершаться с кодом `1` и понятным сообщением, не выполняя
сетевых вызовов.

#### Scenario: Успешный ход
- **WHEN** ключ модели доступен и модель отвечает
- **THEN** выводится итоговый ответ и код возврата равен `0`

#### Scenario: Нет ключа модели
- **WHEN** ключ модели недоступен
- **THEN** выводится сообщение с указанием, где задать ключ, и код возврата
  равен `1`

### Requirement: Интерактивный режим

Команда `chat` SHALL предоставлять линейный цикл «запрос → ход → ответ» в
рамках одной сессии. Цикл MUST завершаться по команде выхода или по концу
потока ввода. При отсутствии интерактивного терминала команда MUST читать
стандартный ввод до конца потока и завершаться с кодом `0`.

#### Scenario: Выход по команде
- **WHEN** в интерактивном режиме введена команда выхода
- **THEN** цикл завершается и код возврата равен `0`

#### Scenario: Конец потока ввода
- **WHEN** стандартный ввод закрыт
- **THEN** цикл завершается и код возврата равен `0`

#### Scenario: Неинтерактивное окружение
- **WHEN** команда запущена без терминала (ввод подан потоком)
- **THEN** обрабатывается весь поданный ввод и команда завершается с кодом `0`

### Requirement: Инспекция сессий

Команда `sessions` SHALL поддерживать перечисление сессий, показ одной сессии
по идентификатору и полнотекстовый поиск по сообщениям. Неизвестный
идентификатор сессии MUST приводить к коду `1`.

#### Scenario: Перечисление
- **WHEN** выполнено `prokop sessions list`
- **THEN** выводится список сессий профиля и код возврата равен `0`

#### Scenario: Поиск по сообщениям
- **WHEN** выполнен поиск по тексту, встречающемуся в сохранённых сообщениях
- **THEN** выводятся совпавшие фрагменты

#### Scenario: Неизвестная сессия
- **WHEN** запрошена сессия с несуществующим идентификатором
- **THEN** выводится сообщение об ошибке и код возврата равен `1`

### Requirement: Управление планировщиком

Команда `cron` SHALL поддерживать перечисление заданий, создание задания с
расписанием и исполнение наступивших заданий (один тик). Некорректная строка
расписания MUST приводить к коду `1` без создания задания.

#### Scenario: Список заданий
- **WHEN** выполнено `prokop cron list`
- **THEN** выводятся задания профиля (или пустой список) и код возврата равен `0`

#### Scenario: Создание задания
- **WHEN** задание создано с корректным расписанием
- **THEN** задание сохраняется в профиле и выводится его идентификатор

#### Scenario: Некорректное расписание
- **WHEN** указано неразбираемое расписание
- **THEN** выводится сообщение об ошибке, задание не создаётся, код возврата
  равен `1`

### Requirement: Инспекция навыков и провайдеров

Команда `skills` SHALL перечислять доступные навыки профиля. Команда
`providers` SHALL перечислять провайдеры моделей, обнаруженные реестром.
Обе команды MUST работать без обращения к сети.

#### Scenario: Список навыков
- **WHEN** выполнено `prokop skills list`
- **THEN** выводятся доступные навыки и код возврата равен `0`

#### Scenario: Список провайдеров
- **WHEN** выполнено `prokop providers list`
- **THEN** выводятся обнаруженные провайдеры и код возврата равен `0`

### Requirement: Конфигурация профиля

Команда `config` SHALL выводить действующую конфигурацию профиля, включая
расположение домашнего каталога профиля. Команда MUST NOT изменять файлы
конфигурации.

#### Scenario: Показ конфигурации
- **WHEN** выполнено `prokop config show`
- **THEN** выводится действующая конфигурация и путь к каталогу профиля

#### Scenario: Отсутствие файла конфигурации
- **WHEN** файл конфигурации отсутствует
- **THEN** выводятся значения по умолчанию, команда завершается с кодом `0`

### Requirement: Управление MCP-серверами из командной строки

CLI SHALL предоставлять подкоманду `mcp` с операциями: перечисление
настроенных серверов, список инструментов указанного сервера и вызов
инструмента сервера с аргументами. Подкоманда MUST быть локальной: она
MUST NOT требовать ключа модели. Аргументы вызова MUST приниматься в виде
JSON-объекта; некорректный JSON MUST приводить к коду возврата `1`.

#### Scenario: Перечисление серверов

- **WHEN** выполнено `prokop mcp list`
- **THEN** выводится список настроенных серверов с признаком включённости и
  код возврата равен `0`

#### Scenario: Инструменты сервера

- **WHEN** выполнено `prokop mcp tools <сервер>`
- **THEN** выводятся инструменты сервера с описаниями и код возврата равен `0`

#### Scenario: Вызов инструмента

- **WHEN** выполнено `prokop mcp call <сервер> <инструмент> --args '<json>'`
- **THEN** результат вызова выводится и код возврата равен `0`

#### Scenario: Некорректные аргументы вызова

- **WHEN** в `--args` передан невалидный JSON
- **THEN** выводится сообщение об ошибке и код возврата равен `1`

#### Scenario: Неизвестный сервер

- **WHEN** указано имя сервера, которого нет в конфигурации
- **THEN** выводится сообщение об ошибке и код возврата равен `1`

#### Scenario: Работа без ключа модели

- **WHEN** ключ модели не задан
- **THEN** подкоманда `mcp` работает и завершается с кодом `0`

### Requirement: Подкоманда `tui`

CLI SHALL предоставлять подкоманду `tui`, запускающую интерактивный
терминальный интерфейс. Подкоманда MUST поддерживать переопределение
провайдера и модели флагами, как у команды хода.

#### Scenario: Справка по подкоманде

- **WHEN** выполнено `prokop tui --help`
- **THEN** выводится справка с флагами `--model` и `--provider` и код
  возврата равен `0`

#### Scenario: Отказ без терминала

- **WHEN** подкоманда запущена без интерактивного терминала
- **THEN** код возврата равен `1`, интерфейс не рисуется

#### Scenario: Нет ключа модели

- **WHEN** ключ модели не задан
- **THEN** выводится сообщение о необходимости ключа и код возврата равен `1`

### Requirement: Подкоманда `checkpoints`

CLI SHALL предоставлять подкоманду `checkpoints` с операциями: список
снимков, создание снимка указанных путей, восстановление из снимка и удаление
старых снимков. Подкоманда MUST быть локальной: она MUST NOT требовать ключа
модели. Восстановление MUST NOT удалять лишние файлы без явного флага.

#### Scenario: Список снимков

- **WHEN** выполнено `prokop checkpoints list`
- **THEN** выводятся снимки профиля (или пустой список) и код возврата равен `0`

#### Scenario: Создание снимка

- **WHEN** выполнено `prokop checkpoints create <путь> [--label L]`
- **THEN** снимок создаётся и выводится его идентификатор

#### Scenario: Восстановление

- **WHEN** выполнено `prokop checkpoints restore <id>`
- **THEN** состояние восстанавливается, выводится отчёт, код возврата равен `0`

#### Scenario: Явное удаление лишних файлов

- **WHEN** восстановление выполнено с флагом удаления лишних файлов
- **THEN** файлы, появившиеся после снимка в снятых каталогах, удаляются

#### Scenario: Неизвестный снимок

- **WHEN** указан идентификатор, которого нет
- **THEN** выводится сообщение об ошибке и код возврата равен `1`

#### Scenario: Несуществующий путь

- **WHEN** указан путь, которого нет
- **THEN** выводится сообщение об ошибке и код возврата равен `1`

#### Scenario: Работа без ключа модели

- **WHEN** ключ модели не задан
- **THEN** подкоманда работает и завершается с кодом `0`

### Requirement: Подкоманда `security`

CLI SHALL предоставлять подкоманду `security` с операциями: показ
действующих правил, проверка конкретной команды без её выполнения и чтение
журнала решений. Подкоманда MUST быть локальной: она MUST NOT требовать ключа
модели. Показ правил MUST содержать явное указание, что слой политик не
изолирует процессы и файловую систему.

#### Scenario: Показ правил

- **WHEN** выполнено `prokop security show`
- **THEN** выводятся запрещающие и разрешающие шаблоны команд и путей, признак
  аудита и указание границ слоя; код возврата равен `0`

#### Scenario: Проверка команды

- **WHEN** выполнено `prokop security check "<команда>"`
- **THEN** выводится решение и причина, команда не выполняется

#### Scenario: Опасная команда в проверке

- **WHEN** проверяется команда, распознанная детектором как опасная
- **THEN** решение — требуется подтверждение, и это видно в выводе

#### Scenario: Запрещённая команда в проверке

- **WHEN** проверяется команда из жёсткого блок-листа
- **THEN** решение — запрет, и это видно в выводе

#### Scenario: Журнал решений

- **WHEN** выполнено `prokop security audit --limit N`
- **THEN** выводятся последние записи журнала (не более N) и код возврата
  равен `0`

#### Scenario: Пустой журнал

- **WHEN** журнал пуст
- **THEN** выводится сообщение об отсутствии записей и код возврата равен `0`

#### Scenario: Работа без ключа модели

- **WHEN** ключ модели не задан
- **THEN** подкоманда работает и завершается с кодом `0`
