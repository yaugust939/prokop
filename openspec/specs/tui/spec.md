# Tui Specification

## Purpose

Интерактивный терминальный интерфейс: состояние сессии, слэш-команды, потоковый вывод, запись сессии, деградация без зависимости и без терминала.

## Requirements

### Requirement: Интерактивный терминальный интерфейс

Ядро SHALL предоставлять интерактивный терминальный интерфейс, запускаемый
командой `prokop tui`, с редактированием ввода, историей введённых строк и
статусной строкой, отражающей провайдера, модель, идентификатор сессии и
число ходов. Ответ модели SHALL выводиться потоково, по мере генерации.

#### Scenario: Запуск интерфейса

- **WHEN** выполняется `prokop tui` в терминале с настроенным ключом модели
- **THEN** открывается интерактивная сессия и приглашение ко вводу

#### Scenario: Статусная строка

- **WHEN** интерфейс активен
- **THEN** статусная строка показывает провайдера, модель, идентификатор
  сессии и число ходов

#### Scenario: Потоковый вывод

- **WHEN** модель отвечает
- **THEN** текст ответа появляется по мере генерации, а не одним блоком в конце

### Requirement: Слэш-команды управления сессией

Интерфейс SHALL поддерживать команды `/help`, `/status`, `/model`,
`/provider`, `/new`, `/sessions`, `/clear`, `/quit`. Строка, не начинающаяся
с `/`, MUST трактоваться как запрос к модели. Неизвестная команда MUST
выводить сообщение об ошибке и MUST NOT завершать интерфейс.

#### Scenario: Справка

- **WHEN** введена команда `/help`
- **THEN** выводится список доступных команд

#### Scenario: Смена модели

- **WHEN** введена команда `/model` с именем модели
- **THEN** последующие ходы используют указанную модель, а статусная строка
  обновляется

#### Scenario: Неизвестный провайдер

- **WHEN** введена команда `/provider` с именем, которого нет в реестре
- **THEN** выводится сообщение об ошибке, текущий провайдер не меняется

#### Scenario: Новая сессия

- **WHEN** введена команда `/new`
- **THEN** создаётся новая сессия, счётчик ходов обнуляется

#### Scenario: Обычный текст уходит модели

- **WHEN** введена строка, не начинающаяся с `/`
- **THEN** строка отправляется модели как запрос

#### Scenario: Выход

- **WHEN** введена команда `/quit`
- **THEN** интерфейс завершается с кодом возврата `0`

### Requirement: Ход сохраняется в хранилище сессий

Интерфейс SHALL создавать сессию с источником `tui` и SHALL записывать в неё
сообщения пользователя и ассистента, чтобы сессия была видна в списке сессий
профиля. Команда `/clear` MUST очищать только историю текущего процесса и
MUST NOT удалять сохранённые записи.

#### Scenario: Сессия видна в списке

- **WHEN** в интерфейсе выполнен ход и интерфейс закрыт
- **THEN** сессия присутствует в списке сессий профиля

#### Scenario: Очистка истории

- **WHEN** введена команда `/clear`
- **THEN** история в памяти сбрасывается, сохранённые сообщения остаются

### Requirement: Деградация без опциональной зависимости

Интерфейс SHALL требовать опциональную зависимость (пакет `prompt_toolkit`).
Если зависимость недоступна, команда MUST вывести сообщение с указанием, как
её установить, и MUST предложить линейный режим вместо падения.

#### Scenario: Зависимость не установлена

- **WHEN** пакет `prompt_toolkit` недоступен
- **THEN** выводится сообщение с командой установки extra и предложение
  использовать линейный режим, процесс не падает

### Requirement: Работа только в терминале

Интерфейс SHALL работать только при наличии терминала. При отсутствии
терминала команда MUST вывести понятное сообщение и MUST завершиться с кодом
возврата `1`, не пытаясь рисовать интерфейс.

#### Scenario: Нет терминала

- **WHEN** команда запущена без интерактивного терминала (ввод подан потоком)
- **THEN** выводится сообщение о необходимости терминала и код возврата `1`

### Requirement: Ошибка хода не завершает интерфейс

Интерфейс SHALL выводить сообщение об ошибке и SHALL продолжать работу, не
завершая сессию, если ход завершился ошибкой (модель недоступна, ошибка
протокола).

#### Scenario: Ошибка модели

- **WHEN** ход завершился ошибкой модели
- **THEN** выводится сообщение об ошибке и приглашение ко вводу остаётся
  доступным
