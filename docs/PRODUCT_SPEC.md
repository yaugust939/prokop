# prokop — продуктовая спецификация

Версия: 0.1.0 · Статус: публичный релиз · Лицензия: MIT

## 1. Обзор продукта

**prokop** — универсальное ядро для построения автономных агентов. Поставляется как
Python-пакет (`pip install -e src`), Docker-образ и интеграция с [opencode](https://opencode.ai)
(MCP-сервер `prokop` + агент `prokop`). Реализовано по поведенческой спецификации
(`openspec/`), покрыто 173 юнит-тестами и проверкой установки в контейнере.

### 1.1 Цель
Дать разработчику готовое, расширяемое, проверенное ядро агента (цикл, инструменты,
память, планировщик, делегирование, исполнение команд), не привязанное к конкретной модели.

### 1.2 Не-цели (0.1)
- Графический интерфейс / десктоп-приложение.
- Реальные адаптеры мессенджеров (гейтвей даёт только абстракцию).
- Обучение/дообучение моделей.

## 2. Пользователи и сценарии

| Роль | Сценарий |
|---|---|
| Разработчик агентов | Встраивает `prokop` как библиотеку, добавляет свои инструменты |
| Инженер автоматизации | Планирует отложенные задания, исполняет команды |
| Пользователь opencode | Общается с агентом `prokop`, зовёт `prokop_agent_turn` и др. |

## 3. Функциональные требования

### 3.1 Ядро
- **Цикл хода (`loop`)**: пролог → итеративный вызов модели с инструментами → финализация.
  Прерывание/steer/redirect, стриминг дельт, бюджеты итераций и настенных часов,
  ретраи с классификацией ошибок, аренда сессии от параллельных ходов.
- **Инструменты (`tools`)**: декларативный реестр, наборы (toolsets) с композицией,
  коэрция аргументов по схеме, разрешения и жёсткий блок-лист опасных команд,
  прогрессивное раскрытие при разрастании поверхности.
- **Навыки (`skills`)**: процедурная память — структура навыка, доступ,
  создание/патч, куратор жизненного цикла (архив без удаления).
- **Память (`memory`)**: контракт провайдеров, менеджер (встроенный первый,
  максимум один внешний), впрыск контекста в пользовательское сообщение.
- **Хранилище сессий (`store`)**: SQLite + полнотекстовый поиск (FTS5, стандартный
  и триграммный индексы), поиск по сессиям с якорным окном, экспорт/импорт.
- **Провайдеры моделей (`providers`)**: декларативные профили, реестр с приоритетами,
  провайдер-агностичное переключение модели без правки кода.
- **Транспорт (`transport`)**: вызовы модели в режиме `chat_completions`
  (сериализация tool_calls в OpenAI-формат для корректного кругового вызова).

### 3.2 Обвес
- **Планировщик (`cron`)**: разбор расписаний (длительность / «каждые …» / крон /
  ISO-время), тикер, исполнение «без агента» (скрипт), доставка результата,
  переживание перезапуска.
- **Субагенты (`subagents`)**: делегирование, изоляция ребёнка, роли лист/оркестратор,
  бюджеты, асинхронный возврат сводки.
- **Терминальные бэкенды (`backends`)**: локальный бэкенд — спавн на команду,
  снимок окружения, обрезка вывода «голова+хвост» со свалкой.
- **Гейтвей (`gateway`)**: ключ сессии, нормализованное событие, контракт адаптера,
  авторизация отправителя, защита от параллельных ходов, кэш агентов, подготовка ответа.

### 3.3 Интеграция с opencode (MCP-сервер `prokop`)
| Инструмент | Назначение |
|---|---|
| `prokop_agent_turn` | Один независимый агентный ход (через модель) |
| `prokop_agent_schedule_job` | Создать задание планировщика |
| `prokop_agent_list_jobs` | Список заданий |
| `prokop_agent_run_ticker` | Исполнить наступившие задания |
| `prokop_agent_run_command` | Команда через терминальный бэкенд |

Агент **`prokop`** в переключателе opencode — универсальный помощник
(личность — `SOUL.md`), использующий эти инструменты.

## 4. Архитектура (высокоуровнево)

```
                      ┌────────────────────────────┐
                      │        prokop (ядро)       │
                      │  loop · tools · skills     │
                      │  memory · store · providers│
                      └──────────────┬─────────────┘
                                     │
        ┌───────────────┬────────────┼───────────────┬───────────────┐
        ▼               ▼            ▼               ▼               ▼
      cron           subagents    backends        gateway        transport
 (планировщик)   (делегирование) (команды)   (мессенджеры)    (вызов модели)
                                     │
                                     ▼
                          MCP-сервер prokop → opencode
```

- Модель подключается через слой провайдеров (по умолчанию — DeepSeek).
- Данные сессий/планировщика — в домашнем каталоге профиля (`~/.prokop`).
- Обвес использует ядро; ядро не зависит от обвеса.

## 5. Нефункциональные требования

- **Тестируемость:** 173 юнит-теста; чистая установка в контейнере прогоняет тесты в сборке.
- **Переносимость:** Python 3.11+; работа на локальной машине и в контейнере.
- **Безопасность:** жёсткий блок-лист опасных команд; секреты — только через переменные
  окружения / `.env` (не в коде и не в git); приватные права на файлы снимков/свалок.
- **Расширяемость:** инструменты, навыки, провайдеры и бэкенды добавляются декларативно.
- **Надёжность:** ретраи транзиентных ошибок, аренда сессии, переживание перезапуска планировщика.
- **Прозрачность:** поведение зафиксировано спецификацией `openspec/`.

## 6. Требования к установке

- Python **3.11+**.
- Зависимости: `httpx`, `PyYAML` (+ `pytest` для тестов).
- Опционально: Docker (для контейнерной установки/проверки).
- Для живых ходов — ключ модели (`DEEPSEEK_API_KEY`).

## 7. Ограничения (известные)

- Гейтвей — абстракция; реальные адаптеры мессенджеров не реализованы.
- Терминальный бэкенд — локальный (Docker/SSH/серверлесс — в роадмапе).
- Планировщик исполняет «без агента» (скрипт); агентный ход в кроне — отложен.

## 8. Роадмап

- **0.2** — терминальные бэкенды: Docker, SSH, серверлесс-песочницы.
- **0.3** — первый реальный адаптер гейтвея + стриминг дельт в транспорте.
- **0.4** — внешние провайдеры памяти, удалённый поиск/хаб навыков.
- **0.5** — TUI/CLI, мастер конфигурации, дрейн/возобновление гейтвея.
- **1.0** — стабильный API, полный паритет со спецификацией, публикация в PyPI.

## 9. Критерии приёмки релиза

- Все тесты зелёные (`pytest`).
- Контейнерная сборка проходит и прогоняет тесты.
- `import prokop` и живой ход через модель работают.
- MCP-сервер `prokop` отдаёт все 5 инструментов; агент `prokop` доступен в opencode.
- Документация (README, GUIDE, FAQ, SOUL) актуальна.
