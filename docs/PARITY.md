# Паритет с аналогами (Hermes Agent и подобные)

Документ фиксирует, где `prokop` не уступает зрелому аналогу, а где отстаёт.
Обновлять при закрытии крупных гэпов.

## Метод

- **prokop**: исходники `src/prokop` (~7.7 тыс. строк), 403 тест, поведенческие
  спеки в `openspec/specs`.
- **Аналог**: публичная документация и агентский гайд Hermes Agent
  (`reference/AGENTS.md`, `reference/website/docs/user-guide/**` — 51 раздел
  возможностей, 35 мессенджеров).
- **Бенчмарк**: `BACKLOG.md` — 9/9 задач у PROKOP, Hermes и OpenClaw.

Сравнивается **поведенческая полнота ядра**, а не объём продукта: Hermes —
это продукт с UX-надстройкой, `prokop` — ядро, на котором такой продукт
собирается.

## Где паритет (ядро не хуже)

| Возможность | prokop | Примечание |
|---|---|---|
| Цикл хода, стриминг, steer/redirect | `loop/*` | байт-стабильный системный промпт, бюджеты итераций и настенных часов |
| Инструменты и наборы | `tools/*` | декларативный реестр, коэрция, разрешения, блок-листы, прогрессивное раскрытие |
| Навыки (процедурная память) | `skills/*` | структура, доступ, самоулучшение, куратор жизненного цикла |
| Память | `memory/*` | контракт провайдеров, менеджер, впрыск контекста |
| Сессии и поиск | `store/*` | SQLite + FTS5, переносимость |
| Провайдеры моделей | `providers/*`, `transport/*` | профили, реестр, смена модели без правки кода |
| Сжатие контекста | `loop/compressor.py` | есть; у Hermes — с кэшированием промпта |
| Планировщик | `cron/*` | разбор расписаний, тикер, «без агента», доставка, переживание перезапуска |
| Делегирование | `subagents/*` | изоляция, роли лист/оркестратор, бюджеты, асинхронный возврат |
| Терминальные бэкенды | `backends/*` | спавн на команду, снимок окружения, обрезка вывода со свалкой |
| Гейтвей (ядро) | `gateway/*` | ключ сессии, нормализованное событие, авторизация, защита от параллельных ходов, кэш агентов |
| GUI-автоматизация | `computer/*` | som/vision/ax, элементы и координаты; cua-driver + локальный Windows |
| Кросс-проектная диспетчеризация | `orchestrator/*` | headless-сессии opencode + отчёт в трекер (MVP) |
| Командная строка | `cli/*` | команда `prokop`: `turn`, `chat`, `sessions`, `skills`, `providers`, `config`, `doctor`, `cron`, `mcp`; `--json`, коды возврата |
| MCP-клиент | `mcp/*` | общий клиент внешних MCP-серверов по stdio; инструменты серверов в реестре ядра (`mcp__<сервер>__<инструмент>`) |
| Терминальный интерфейс | `tui/*` | `prokop tui`: редактирование, история, статусная строка, слэш-команды, потоковый вывод, запись сессии; extra `tui` |
| Снимки и откат | `checkpoints/*` | `prokop checkpoints list\|create\|restore\|prune`; безопасный откат (лишние файлы только по флагу), страховочный снимок, потолки; инструмент `checkpoint` |
| Политики безопасности | `security/*` | `prokop security show\|check\|audit`; deny/allow для команд и путей, единая точка решения, журнал JSONL. Границы: не песочница |

## Вывод

- **Ядро агента у prokop на уровне**: цикл хода, инструменты, навыки, память,
  сессии, планировщик, делегирование, терминальные бэкенды, гейтвей-ядро,
  GUI-автоматизация и командная строка закрыты собственными спеками и
  тестами; бенчмарк 9/9.
- **Отставание — в интеграциях и UX-обвязке**, а не в качестве ядра. Это
  ожидаемо: Hermes — продукт, `prokop` — ядро.
- Чтобы «не хуже» стало проверяемым утверждением, а не лозунгом, закрывать
  гэпы нужно по приоритету: изоляция процессов и файловой системы (песочница —
  платформенно-специфична), и хотя бы один-два реальных адаптера мессенджеров и
  memory-провайдера как доказательство расширяемости контрактов.

## Закрытые гэпы

| Гэп | Изменение | Что сделано |
|---|---|---|
| CLI | `prokop-cli` | команда `prokop` с локальными и сетевыми командами, `--json`, фиксированные коды возврата, кроссплатформенный stdio |
| MCP-клиент | `mcp-client` | общий клиент MCP по stdio, секция `mcp.servers` в профиле, мост инструментов в реестр ядра, подкоманда `prokop mcp` |
| TUI | `prokop-tui` | `prokop tui`: редактирование, история, статусная строка, слэш-команды, потоковый вывод, запись сессии; опциональный extra `tui` |
| Checkpoints и откат | `prokop-checkpoints` | снимки путей, откат со страховочным снимком, безопасное поведение по умолчанию, потолки и игнорирование, инструмент `checkpoint` |
| Слой политик безопасности | `prokop-security` | deny/allow для команд и путей, единая точка решения с фиксированным приоритетом, аудит решений, инспекция из CLI. Границы слоя заявлены явно |

## Как закрывать

Крупные гэпы — только через OpenSpec (`/opsx-propose` → `/opsx-apply`), по
одному изменению на гэп, со синхронизацией спек в `openspec/specs` и
архивацией по завершении. Операционные задачи — в `.hermes/tasks.md`.
