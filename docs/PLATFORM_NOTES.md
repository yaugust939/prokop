# Платформенные заметки

Здесь собраны отличия окружений, которые **не должны протекать в ядро**.
Правило: код ядра не ветвится по ОС ради путей и не содержит личных
абсолютных путей. Всё платформенное — либо в этом файле, либо в явной
точке с комментарием.

## Инварианты

1. **Один резолвер состояния** — `prokop.home` (`PROKOP_HOME` или
   `~/.prokop`; профиль — `PROKOP_PROFILE` или `default`). Именованные
   подкаталоги (логи, БД, провайдеры) — в `prokop.paths`. Других способов
   вычислить домашний каталог в ядре нет.
2. **Раскладка каталогов одинакова везде.** Никаких `%LOCALAPPDATA%`,
   `~/Library/Application Support` и прочих системных баз по умолчанию:
   среда задаётся переменной `PROKOP_HOME`, а не ветвлением по платформе.
3. **Никаких личных путей** (`C:\Users\<имя>\...`, `/home/<имя>/...`) в
   исходниках. Проверяется в CI (job `hygiene`).
4. **Личность (`SOUL.md`) платформенно-нейтральна.** Механика конкретной
   ОС (PowerShell-касты, `taskkill` и т.п.) живёт здесь, а не в душе агента.
5. **Кодировка вывода команд фиксирована.** Терминальный бэкенд декодирует
   вывод дочернего процесса как UTF-8 с заменой и задаёт ребёнку
   `PYTHONUTF8=1` / `PYTHONIOENCODING=utf-8`. Результат команды не зависит
   от локали машины и переменных окружения вызывающей стороны; явные
   значения из аргумента `env` или снимка сессии сохраняют приоритет.

## Точки, где платформа реально различается

| Место | Windows | POSIX |
|---|---|---|
| `orchestrator/spawn.py` | `CREATE_NO_WINDOW`, поиск `opencode.exe` в `%APPDATA%\npm` | `start_new_session=True` (лидер группы процессов), поиск бинаря в `~/.npm-global`, `~/.local`, `/usr/local` |
| `orchestrator/collect.py` | `taskkill /PID <pid> /T /F` | `killpg(SIGKILL)` с откатом на `SIGTERM` |
| `backends/local.py` | `taskkill /F /T /PID` | `killpg(SIGKILL)` с откатом на `SIGTERM` |
| `cron/store.py::_FileLock` | `O_CREAT\|O_EXCL`-маркер + перехват устаревшего по `mtime` | `fcntl.flock(LOCK_EX\|LOCK_NB)` |
| `computer/windows.py` | локальный GUI-бэкенд (mss + pyautogui + pywinauto UIA) | нет локального бэкенда — используйте `cua-driver` (`computer/cua.py`) |
| extra `gui` в `pyproject.toml` | `mss`, `Pillow`, `pyautogui`, `pywinauto` | `mss`, `Pillow` |

Все ветвления — точечные (`os.name == "nt"` / `sys.platform == "win32"`)
и имеют рабочий фолбэк. Спецификация не должна описывать их безусловно.

## PowerShell (Windows) — заметки для агента

Полезно при работе в PowerShell; на других платформах неприменимо.

- **Явная конвертация типов.** `[int](Get-Content ...)` вместо авто-каста:
  `Measure-Object`/`Get-Content` возвращают объекты/массивы, авто-каст
  склеивает строки вместо арифметики.
- **Кодировка вывода.** Вывод дочерних процессов декодируется как UTF-8
  (см. инвариант 5), поэтому моджибейка нет. Обратная сторона: нативные
  утилиты Windows, печатающие в OEM-кодировке (`dir`, `chcp`), дадут символы
  замены — осознанный компромисс в пользу детерминизма. Перенаправленный
  JSON-вывод из PowerShell может прийти в UTF-16: предпочитайте запуск
  процесса из Python (`subprocess`), а не редирект в PowerShell.
- **Файловые операции.** Перед `Remove-Item -Recurse` — сначала
  `Get-ChildItem` (убедиться, что удаляется именно то). Контролировать
  переносы строк при `Add-Content`/`Set-Content`.
- **Пути.** Кириллица и пробелы в путях передаются списком аргументов
  (`subprocess.Popen([...])`), а не строкой консоли.

## Проверка перед итерацией (универсально)

Независимо от платформы: перед следующим шагом посмотреть `git status`,
промежуточные файлы и вывод последней команды — не начинать новую
итерацию вслепую.
