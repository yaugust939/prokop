# Регламент чистой комнаты (clean room)

Проект `OBS_Prokopii_1` — оригинальная («чистая») пересборка агента-диспетчера,
совместимая по поведению с бенчмарком **NousResearch/hermes-agent**, но написанная
с нуля без копирования исходного кода.

## 1. Цель

Обеспечить гарантированную оригинальность кодовой базы: реализация пишется
только по поведенческой спецификации, полученной из эталона. Совпадение
интерфейсов и поведения — допустимо; копирование кода, структуры модулей,
строк и имён — запрещено.

> Юридическая поправка: эталон распространяется под MIT-лицензией, поэтому
> копирование с сохранением лицензии законно. Clean room здесь применяется не
> как защита от иска, а как гарантия оригинальности и чистоты сборки.

## 2. Предмет барьера

Репозиторий `reference\` — клон `nousresearch/hermes-agent`, закреплённый на
коммите `e5032945cbebb64b8a819b66ec831c1906297b81`. Изучению подлежит текущее
дерево (поведение), история коммитов не используется.

## 3. Роли и зоны

| Роль | Агент | Доступ | Что делает |
|------|-------|--------|------------|
| Команда A | `explore` | `reference\` + `openspec\changes\` | Читает эталон, извлекает *поведение*, пишет спецификацию OpenSpec |
| Команда B | `general` | только `openspec\changes\` → `src\` | Реализует код строго по спецификации |
| Диспетчер | `hermes` | всё | Выдаёт задачи, держит барьер, ведёт `clean-room\log.md` |

## 4. Правила барьера

### Команда A (explore) — МОЖНО
- Читать любые файлы `reference\`.
- Формулировать поведение, интерфейсы, форматы данных, контракты тулов.
- Писать результат в `openspec\changes\` (OpenSpec change).

### Команда A — НЕЛЬЗЯ
- Копировать фрагменты кода, дословные строки, имена модулей/классов в spec.
- Передавать B содержимое `reference\` напрямую.

### Команда B (general) — МОЖНО
- Читать только `openspec\changes\`.
- Писать код в `src\`.

### Команда B — НЕЛЬЗЯ
- Открывать/читать `reference\` (любой файл).
- Получать содержимое `reference\` через промпт.
- Использовать `reference\` как источник в любом виде.

### Диспетчер (hermes)
- В каждом задании для B явно указывает: «НЕ читать `reference\`».
- Не вставляет содержимое `reference\` в промпты для B.
- Фиксирует каждую выдачу доступа в `log.md`.

## 5. Процесс

```
reference\ ──A(explore)──> openspec\changes\ (OpenSpec) ──B(general)──> src\
```

1. **Спецификация.** A запускает `/opsx-propose` по поведению эталона →
   создаётся OpenSpec change в `openspec\changes\`.
2. **Реализация.** B запускает `/opsx-apply` по задачам change → код в `src\`.
3. **Приёмка.** Диспетчер проверяет: `src\` не содержит дословных фрагментов
   эталона; `log.md` не содержит строки `B → reference\`.

## 6. Фазы

- **Ядро:** agent loop, tools/toolsets, skills, память, providers.
- **Обвес (после ядра):** gateway/мессенджеры, cron, TUI/web, MCP, бэкенды.

Каждая фаза — отдельный OpenSpec change и отдельный цикл A → B.

## 7. Ограничение opencode

Агенты живут в общей файловой системе и общем контексте — физической изоляции
(как в классической clean room) нет. Барьер держится на процедурной дисциплине
и контроле диспетчера. Для судебной значимости потребуется дополнительная
изоляция на уровне ОС — вне рамок этого регламента.

## 8. Критерии оригинальности

1. Весь код `src\` написан только по `openspec\changes\`.
2. В `src\` нет дословных фрагментов, строк, имён модулей из `reference\`.
3. `clean-room\log.md` не содержит записи `B → reference\`.
4. Каждая фаза имеет закрытый OpenSpec change.

## 9. Гибридная стратегия (решение от 2026-08-25)

Решение Фазы 0: проект переходит в гибридный режим.

- Ядро (`agent_core`: agent-loop, tools/toolsets, skills, memory, providers)
  остаётся предметом чистой комнаты — пишется только по `openspec\changes\`,
  барьер A/B сохраняется.
- Обвес (каналы мессенджеров, планировщик, делегирование, сэндбоксы, гейтвей,
  UI) выносится во второй проект `D:\OBS_SparkDesign_AgentScope` и собирается
  поверх готовых сторонних фреймворков **AgentScope 2.0** (рантайм,
  Apache-2.0) и **Spark Design System** (React/TS UI, Apache-2.0) как внешних
  зависимостей, вне барьера чистой комнаты.
- Код третьей стороны (agentscope, @agentscope-ai/*, Ant Design) не является
  предметом чистоты; собственный код гибрида (шов к ядру, кастомные каналы)
  пишется с нуля по концепции `D:\OBS_SparkDesign_AgentScope\KONCEPT.md`.
- Правило «B → reference\» действует только для зоны ядра; для обвеса чтение
  документации/кода AgentScope и Spark Design разрешено обеим ролям.
- Собственный обвес из `src\agent_core` (gateway, cron, subagents, backends)
  переводится в статус fallback/референс и в гибриде замещается блоками
  AgentScope.
